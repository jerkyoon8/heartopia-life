# Project Principles

## Code Quality

- 기존 코드 스타일과 구조를 우선한다.
- 새 추상화는 중복이나 복잡도를 실제로 줄일 때만 만든다.
- 기능과 무관한 리팩터링은 분리한다.

## Testing

- 핵심 사용자 흐름과 위험한 변경에는 테스트를 둔다.
- 버그 수정은 가능하면 회귀 테스트를 함께 추가한다.
- 테스트를 생략하면 이유와 남은 리스크를 기록한다.

## User Experience

- 사용자가 가장 자주 하는 작업을 가장 짧은 경로로 처리한다.
- 빈 상태, 오류 상태, 로딩 상태를 고려한다.
- 화면 문구는 기능 설명보다 사용자의 다음 행동을 돕는 데 집중한다.

## Performance

- 성능 목표가 필요한 경우 측정 가능한 기준으로 적는다.
- 초기 구현에서 불필요한 캐시, 큐, 분산 구조는 피한다.

## Security And Privacy

- 민감 정보는 로그, 에러 메시지, 클라이언트 저장소에 노출하지 않는다.
- 입력값 검증과 권한 확인은 서버 또는 신뢰 가능한 경계에서 수행한다.

## Scope Control

- MVP 범위와 비목표를 명확히 둔다.
- 새 요구사항은 구현 중 바로 끼워 넣지 않고 Spec 또는 Plan에 먼저 반영한다.
