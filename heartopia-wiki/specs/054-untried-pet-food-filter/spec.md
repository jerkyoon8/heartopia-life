# Feature Spec: 안 먹여본 음식 필터

## Source

- PRD: `specs/054-untried-pet-food-filter/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 안 먹여본 음식만 보기

- Given 반려동물이 선택되어 있고 일부 음식에 먹여봄 기록이 있다.
- When 사용자가 `안 먹여본 음식` 필터를 선택한다.
- Then 먹여봄 기록이 없는 음식만 목록에 표시된다.

### Scenario 2: 검색어와 함께 사용

- Given `안 먹여본 음식` 필터가 선택되어 있다.
- When 사용자가 음식 이름 또는 재료 검색어를 입력한다.
- Then 안 먹여본 음식 중 검색어와 일치하는 음식만 표시된다.

### Scenario 3: 현재 결과에서 먹여봄 처리

- Given `안 먹여본 음식` 필터 결과가 표시되어 있다.
- When 사용자가 음식의 먹여봄 상태를 체크한다.
- Then 해당 음식은 현재 결과에서 즉시 사라진다.

## Functional Requirements

- FR-001: 시스템은 기존 필터 탭에 `안 먹여본 음식` 버튼을 제공해야 한다.
- FR-002: 시스템은 `pet.tried[food.id]`가 참이 아닌 음식을 안 먹여본 음식으로 판단해야 한다.
- FR-003: 시스템은 음식 검색 조건과 미시도 조건을 동시에 적용해야 한다.
- FR-004: 시스템은 현재 선택한 반려동물의 기록만 기준으로 필터링해야 한다.
- FR-005: 시스템은 기존 네 가지 필터의 동작을 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 버튼은 기존 필터 버튼과 동일한 스타일·활성 상태·키보드 접근 방식을 사용해야 한다.
- NFR-002: 저장 형식, 로그인 동기화 API, 데이터베이스 스키마를 변경하지 않아야 한다.

## Edge Cases

- 먹여본 기록이 하나도 없으면 모든 음식이 안 먹여본 음식 결과에 표시된다.
- 모든 음식을 먹여봤으면 기존 `조건에 맞는 음식이 없습니다.` 안내가 표시된다.
- 반려동물을 선택하지 않았으면 기존 반려동물 등록 안내가 유지된다.
- 존재하지 않거나 거짓 값인 `tried` 항목은 안 먹여본 것으로 취급한다.

## Data Requirements

- 기존 반려동물 프로필의 `tried` 객체만 읽는다.
- 필터 상태는 화면 상태이며 별도로 저장하거나 서버에 전송하지 않는다.

## Clarifications

- Q: 미시도 음식 개수도 요약 카드에 추가하는가?
  A: 이번 문의는 탐색 시간을 줄이는 버튼 요청이므로 필터 버튼만 추가한다.
- Q: 로그인 사용자와 비로그인 사용자를 다르게 처리하는가?
  A: 아니다. 둘 다 화면에 로드된 동일한 프로필 구조를 사용한다.
