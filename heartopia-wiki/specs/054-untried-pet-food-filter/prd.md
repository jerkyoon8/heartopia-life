# PRD: 안 먹여본 음식 필터

## 1. Summary

### Problem

반려동물에게 먹인 음식이 많아질수록 아직 먹이지 않은 음식을 찾기 위해 긴 목록을 직접 스크롤해야 한다.

### Proposed Solution

반려동물 먹이 기록의 기존 필터 탭에 `안 먹여본 음식` 버튼을 추가해, 선택한 반려동물에게 먹여본 기록이 없는 음식만 즉시 표시한다.

### Success Criteria

- 선택한 반려동물 기준으로 먹여본 기록이 없는 음식만 표시된다.
- 검색어와 안 먹여본 음식 필터를 함께 사용할 수 있다.
- 기존 전체, 먹여본 음식, 좋아하는 음식, 싫어하는 음식 필터 동작은 변하지 않는다.

## 2. Users And Use Cases

### Primary Users

- 반려동물의 선호 먹이를 찾기 위해 먹이 시도 여부를 기록하는 사용자

### User Stories

- As a 반려동물 기록 사용자, I want to 아직 먹이지 않은 음식만 모아 보고, so that 다음에 시험할 먹이를 빠르게 고를 수 있다.

## 3. Functional Scope

### In Scope

- 기존 음식 필터 탭에 `안 먹여본 음식` 버튼 추가
- 선택한 반려동물의 `tried` 기록이 없는 음식만 필터링
- 기존 음식명·재료 검색 조건과 교차 적용
- 로컬 서버에서 회귀 및 화면 동작 검증

### Out Of Scope

- 저장 데이터 구조 및 API 변경
- 미시도 음식 개수 요약 카드 추가
- 운영 서버 배포 및 Git push

## 4. Acceptance Criteria

- 반려동물을 선택하고 `안 먹여본 음식`을 누르면 `tried[food.id]`가 참이 아닌 음식만 보인다.
- 먹여봄 체크를 변경하면 현재 필터 결과가 즉시 갱신된다.
- 다른 반려동물을 선택하면 해당 반려동물의 기록을 기준으로 결과가 계산된다.
- 검색 결과가 없으면 기존 빈 결과 안내가 표시된다.
- 로그인 여부와 관계없이 화면에 로드된 동일한 프로필 데이터 구조를 사용한다.

## 5. Constraints

- Tech: 기존 Thymeleaf 단일 페이지와 Vanilla JavaScript 필터 구조를 유지한다.
- Time: 현재 로컬 변경 범위로 완료한다.
- Data: 기존 `pet.tried` 객체를 그대로 사용하며 마이그레이션은 하지 않는다.
- External Dependencies: 없음.

## 6. Risks

- 문자열 필터 분기 누락: 기존 필터 회귀 테스트와 로컬 브라우저 테스트로 확인한다.

## 7. Open Questions

- 없음. 문의 내용과 기존 UI 패턴으로 동작 범위가 명확하다.
