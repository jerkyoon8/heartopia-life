# Feature Spec: 모바일 메인 카드 고밀도 배치

## Source

- PRD: `specs/020-mobile-wiki-two-column/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 모바일에서 바로가기 탐색

- Given 사용자가 576px 이하 화면에서 메인 페이지를 연다.
- When 선물 코드와 마을 지도 바로가기를 확인한다.
- Then 두 카드가 한 줄에 함께 표시되고 각 카드 전체를 누를 수 있다.

### Scenario 2: 모바일에서 도감 탐색

- Given 사용자가 576px 이하 화면에서 도감·취미·기타 정보 영역을 본다.
- When 카드 목록을 스크롤한다.
- Then 한 줄에 네 카드가 표시되고 아이콘과 제목으로 항목을 구분할 수 있다.

### Scenario 3: 큰 화면 유지

- Given 사용자가 태블릿 또는 데스크톱 화면을 사용한다.
- When 메인 페이지를 연다.
- Then 기존 반응형 열 수와 카드 구성이 유지된다.

## Functional Requirements

- FR-001: 시스템은 576px 이하에서 메인 바로가기 카드를 2열로 표시해야 한다.
- FR-002: 시스템은 576px 이하에서 모든 `.wiki-grid`를 4열로 표시해야 한다.
- FR-003: 모바일 정보 카드는 아이콘과 최대 두 줄 제목을 중심으로 표시해야 한다.
- FR-004: 모바일 바로가기 카드는 제목, 핵심 설명 또는 상태, 이동 버튼을 카드 안에 표시해야 한다.
- FR-005: 카드 링크의 기존 목적지와 순서를 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 360px 이상에서 문서 가로 스크롤이 발생하지 않아야 한다.
- NFR-002: 카드 전체 터치 영역은 최소 80px 높이를 유지해야 한다.
- NFR-003: 다크모드와 라이트모드에서 기존 색상 대비를 유지해야 한다.
- NFR-004: 변경으로 브라우저 콘솔 오류가 발생하지 않아야 한다.

## Edge Cases

- 긴 카드 제목: 최대 두 줄 안에서 자연스럽게 줄바꿈하고 영역을 넘지 않는다.
- 데이터 수: 모바일에서는 숨겨 카드 밀도를 높인다.
- 준비 중 카드: 기존 비활성 상태와 표시를 유지한다.
- 360px 화면: 두 열의 카드가 겹치거나 잘리지 않는다.

## Data Requirements

- 새로운 데이터는 필요하지 않다.
- 기존 서버 렌더링 카드 데이터와 링크를 그대로 사용한다.

## Clarifications

- Q: 모든 모바일 목록을 2열로 변경하는가?
  A: 아니다. 사용자가 제공한 스크린샷에 나온 메인 페이지 바로가기와 메인 정보 카드만 변경한다.
- Q: 공통 헤더도 함께 변경하는가?
  A: 이번 작업에서는 변경하지 않는다.
- Q: 모바일 정보 카드는 몇 열인가?
  A: 사용자의 후속 결정에 따라 4열이며, 바로가기 카드만 2열을 유지한다.
