# PRD: 모바일 메인 카드 고밀도 배치

## 1. Summary

### Problem

모바일 메인 페이지의 바로가기와 도감 카드가 한 줄에 하나씩 크게 표시되어, 사용자가 원하는 항목을 찾기 위해 지나치게 많이 스크롤해야 한다.

### Proposed Solution

메인 페이지의 바로가기 카드는 모바일 2열을 유지하고, 도감·취미·기타 정보 카드는 한 줄에 네 개씩 표시한다. 정보 카드는 아이콘과 제목 중심으로 단순화해 탐색 밀도를 높인다.

### Success Criteria

- 360~576px 화면에서 바로가기는 2열, 정보 카드는 4열로 표시된다.
- 360px 화면에서도 가로 스크롤이나 카드 겹침이 발생하지 않는다.
- 카드 제목과 핵심 상태가 잘리지 않고 링크 전체를 터치할 수 있다.

## 2. Users And Use Cases

### Primary Users

- 휴대전화로 메인 페이지의 도감과 바로가기를 탐색하는 사용자

### User Stories

- 모바일 사용자로서 한 화면에서 더 많은 항목을 보고, 원하는 도감으로 빠르게 이동하고 싶다.

## 3. Functional Scope

### In Scope

- 메인 페이지의 선물 코드·마을 지도 바로가기 모바일 2열 배치
- 도감·취미·기타 정보 카드 모바일 4열 배치
- 정보 카드의 데이터 개수는 모바일에서 숨기고 준비 중 상태는 유지
- 모바일 카드 이미지, 글자, 간격, 높이 조정
- 다크모드와 라이트모드의 기존 색상 유지

### Out Of Scope

- 다른 도감 목록 페이지의 카드 배치 변경
- 공통 헤더 구조 변경
- 데스크톱·태블릿의 기존 열 수 변경
- 메인 페이지 정보 구조나 카드 순서 변경

## 4. Acceptance Criteria

- 576px 이하에서 바로가기는 2열, 정보 카드는 4열이다.
- 360px과 375px에서 제목이 최대 두 줄 안에 표시된다.
- 카드 사이 간격과 터치 영역이 유지된다.
- 768px 이상에서는 기존 레이아웃이 유지된다.
- 브라우저 콘솔 오류와 가로 오버플로가 없다.

## 5. Constraints

- Tech: 기존 `wiki.html`의 인라인 CSS와 Thymeleaf 마크업을 유지한다.
- Time: 현재 수정 범위 안에서 완료한다.
- Data: 서버 데이터와 카드 순서를 변경하지 않는다.
- External Dependencies: 없음.

## 6. Risks

- 긴 제목이 좁은 카드에서 과도하게 줄바꿈될 수 있음: 모바일 전용 글자 크기와 줄바꿈 규칙으로 완화한다.
- 카드가 너무 작아 터치하기 어려울 수 있음: 카드 전체 링크와 충분한 최소 높이를 유지한다.

## 7. Open Questions

- 없음. 사용자가 제공한 메인 페이지 스크린샷을 범위 기준으로 사용한다.
