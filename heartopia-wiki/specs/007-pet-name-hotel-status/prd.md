# PRD: 반려동물 이름 수정 및 호텔 상태

## 1. Summary

### Problem

등록한 반려동물의 이름을 나중에 고칠 수 없고, 호텔에 맡긴 반려동물을 별도로 표시할 수 없다. 사용자는 최대 5마리인 호텔 입실 현황을 화면에서 바로 구분하고 싶다.

### Proposed Solution

선택한 반려동물의 이름을 인라인으로 수정할 수 있게 하고, 각 반려동물에 호텔 입실 상태를 저장한다. 호텔 입실은 전체 등록 반려동물 중 최대 5마리로 제한하며, 목록과 선택 영역에서 입실 상태를 시각적으로 강조한다.

### Success Criteria

- 등록된 반려동물 이름을 수정하고 새로고침 후에도 변경된 이름을 확인할 수 있다.
- 호텔 입실 상태를 켜고 끌 수 있으며 목록에서 즉시 구분할 수 있다.
- 호텔 입실 상태인 반려동물은 동시에 5마리를 초과할 수 없다.
- 로컬 저장과 로그인 동기화 양쪽에서 이름과 호텔 상태가 유지된다.

## 2. Users And Use Cases

### Primary Users

- 반려동물과 먹이 기록을 관리하는 비로그인·로그인 사용자

### User Stories

- 사용자로서 잘못 입력했거나 바뀐 반려동물 이름을 수정하고 싶다.
- 사용자로서 호텔에 맡긴 반려동물을 체크하고 목록에서 바로 알아보고 싶다.
- 사용자로서 호텔 정원 5마리를 넘겨 잘못 기록하지 않도록 안내받고 싶다.

## 3. Functional Scope

### In Scope

- 선택한 반려동물 이름 수정
- 반려동물별 호텔 입실/퇴실 상태 토글
- 전체 프로필 기준 호텔 입실 최대 5마리 제한
- 반려동물 목록과 선택 영역의 호텔 상태 강조
- 기존 로컬 저장 및 로그인 DB 동기화 JSON 확장
- 서버의 호텔 상태 타입과 최대 개수 검증
- 기존 데이터의 하위 호환 정규화

### Out Of Scope

- 호텔 입실일, 퇴실 예정일 또는 객실 정보
- 호텔 내 반려동물 순서 관리
- 호텔 상태만 별도로 조회하는 서버 API
- 반려동물 종류 수정
- DB 테이블 또는 컬럼 추가

## 4. Acceptance Criteria

- 선택한 반려동물에서 이름 수정 버튼을 누르면 현재 이름이 입력된 편집 UI가 열린다.
- 앞뒤 공백을 제거한 1~80자 이름만 저장할 수 있다.
- 기존 등록 정책과 동일하게 서로 다른 반려동물의 같은 이름은 허용한다.
- 호텔 입실 체크 시 프로필의 `inHotel` 값이 `true`, 해제 시 `false`로 저장된다.
- 이미 5마리가 입실한 상태에서 다른 반려동물을 체크하면 상태를 바꾸지 않고 안내한다.
- 입실한 반려동물은 목록 칩에 `호텔` 배지가 나타나고 일반 반려동물과 시각적으로 구분된다.
- 기존 저장 데이터에 `inHotel`이 없으면 퇴실 상태로 처리한다.
- 로그인 동기화 서버는 `inHotel`이 불리언이 아니거나 입실 프로필이 5개를 초과하면 HTTP 400으로 거부한다.

## 5. Constraints

- Tech: Java 17, Spring Boot, Thymeleaf, Vanilla JS, 기존 `user_pet_food.pets_json`
- Time: 기존 반려동물 관리 화면과 저장 API를 최소 범위로 확장
- Data: 기존 프로필 JSON과 하위 호환, 별도 SQL 마이그레이션 없음
- External Dependencies: 없음

## 6. Risks

- 오래된 데이터에 신규 필드가 없음: 클라이언트에서 `false`로 정규화하고 서버는 필드 누락을 허용한다.
- 클라이언트 제한 우회: 서버에서도 전체 프로필의 호텔 입실 개수를 검증한다.
- 현재 `pets.html`의 이미지 별칭 수정과 충돌: 해당 사용자 변경을 보존하고 이름·호텔 관련 구간만 수정한다.
