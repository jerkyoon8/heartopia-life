# Feature Spec: 고래낙하 협곡 동물 위치 지정

## Source

- PRD: `specs/011-animal-second-map-placement/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 고래낙하 협곡 동물 등록

- Given 관리자가 동물 도감 페이지에 로그인해 있다.
- When 동물 추가 모달에서 위치를 `고래낙하 협곡`으로 선택하고 저장한다.
- Then 동물 데이터의 위치가 정확히 `고래낙하 협곡`으로 저장된다.

### Scenario 2: 두 번째 지도에서 동물 배치

- Given 위치가 `고래낙하 협곡`인 동물이 아직 지도에 배치되지 않았다.
- When 관리자가 `고래낙하 협곡` 지도를 열고 동물의 위치 지정 버튼을 누른 뒤 지도 한 지점을 클릭한다.
- Then 해당 좌표와 `second` 지도 키를 가진 동물 핀이 저장되고 즉시 표시된다.

### Scenario 3: 지도별 동물 분리

- Given 기본 지도 동물과 고래낙하 협곡 동물이 모두 등록되어 있다.
- When 사용자가 각 지도를 전환한다.
- Then 기본 지도에는 기본 동물만, 고래낙하 협곡 지도에는 고래낙하 협곡 동물만 노출된다.

### Scenario 4: 기존 동물 수정

- Given 위치가 `고래낙하 협곡`인 동물이 저장되어 있다.
- When 관리자가 해당 동물의 수정 모달을 연다.
- Then 위치 선택값이 `고래낙하 협곡`으로 복원되고 다른 값으로 변경할 수 있다.

## Functional Requirements

- FR-001: 시스템은 동물 추가·수정 모달에서 위치를 선택할 수 있게 해야 한다.
- FR-002: 위치 선택지에는 기존 기본 지도 위치와 `고래낙하 협곡`이 포함되어야 한다.
- FR-003: 시스템은 동물 지도 API의 `mapKey` 요청값을 처리해야 한다.
- FR-004: 위치가 `고래낙하 협곡`인 동물은 `second` 지도에만 귀속되어야 한다.
- FR-005: 그 외 동물은 기존 호환성을 위해 기본 지도 `town`에 귀속되어야 한다.
- FR-006: 두 번째 지도에 귀속된 미배치 동물도 관리자 사이드바에 표시되어야 한다.
- FR-007: 관리자가 두 번째 지도에서 동물 핀을 배치하면 핀의 `mapKey`는 `second`로 저장되어야 한다.
- FR-008: 지도 선택 버튼은 사용자에게 `고래낙하 협곡`으로 표시되어야 한다.
- FR-009: 이벤트명 `고래 탐사 시즌`과 내부 지도 키 `second`는 변경하지 않아야 한다.
- FR-010: 고래낙하 협곡 지도는 첫 진입 시 전체 카테고리·핀·구역 표시를 활성화해야 한다.
- FR-011: 기본 지도 `town`의 기존 초기 표시 정책은 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 핀 생성·수정·삭제의 기존 관리자 권한 정책을 유지해야 한다.
- NFR-002: 기존 데이터에 새 DB 열이나 마이그레이션을 요구하지 않아야 한다.
- NFR-003: 기존 기본 지도 동물과 다른 도감 종류의 지도 동작을 변경하지 않아야 한다.
- NFR-004: 지도별 동물 필터링은 서버 응답과 클라이언트 표시에서 일관되어야 한다.

## Edge Cases

- `mapKey`가 없거나 공백이면 기존처럼 기본 지도 `town`으로 처리한다.
- 알 수 없는 `mapKey`는 기존 정규화 정책을 유지하되 고래낙하 협곡 동물을 반환하지 않는다.
- 위치가 비어 있거나 기존 자유 입력값인 동물은 기본 지도 동물로 취급한다.
- 수정 대상의 기존 위치가 현재 선택지에 없으면 값이 유실되지 않도록 호환 선택지를 동적으로 보존한다.
- 같은 이름의 핀이 다른 지도에 있더라도 활성 지도 핀만 배치 여부 판단에 사용한다.

## Data Requirements

- 동물의 기존 `animal_collections.location` 값을 지도 귀속 판정에 사용한다.
- `location = '고래낙하 협곡'`이면 내부 지도 키를 `second`로 계산한다.
- 핀은 기존 `map_pins.map_key`, `category = 'animal'`, `name`, `map_x`, `map_y` 구조에 저장한다.
- 이번 기능에는 DB 스키마 변경이나 초기 데이터 SQL이 없다.

## Clarifications

- Q: 정식 장소명은 무엇인가?
  A: `고래낙하 협곡`이다.
- Q: 지도 버튼명도 변경하는가?
  A: 두 번째 지도 버튼은 `고래낙하 협곡`으로 표시한다.
- Q: 이벤트명도 변경하는가?
  A: 아니다. 이벤트명 `고래 탐사 시즌`은 유지한다.
- Q: 물고기·곤충·새 등에도 같은 규칙을 적용하는가?
  A: 아니다. 이번에는 동물에만 적용하고 필요할 때 확장한다.
- Q: 고래낙하 협곡의 초기 표시 상태는 무엇인가?
  A: `전체 표시`를 누른 것처럼 모든 카테고리·핀·구역을 켠 상태다.
