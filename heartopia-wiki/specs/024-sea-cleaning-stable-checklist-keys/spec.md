# Feature Spec: 바다청소 체크리스트 ID 키 전환

## Source

- PRD: `specs/024-sea-cleaning-stable-checklist-keys/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 로컬 체크리스트 최초 전환

- Given 브라우저에 이름 기반 바다청소 별점과 명인 키가 저장되어 있다.
- When 사용자가 ID 키 전환 후 바다청소 또는 전체 체크리스트 페이지를 처음 연다.
- Then 일반·명인 키가 해당 항목의 DB ID 키로 바뀌고 마이그레이션 버전이 기록된다.

### Scenario 2: 장기 미접속 후 이름 변경

- Given 사용자가 ID 전환 배포 전 상태로 장기간 미접속했고 관리자가 그동안 조개 이름을 변경했다.
- When 사용자가 나중에 새 사이트를 열어 구형 로컬 키를 제공한다.
- Then 변경되지 않은 레거시 별칭을 통해 ID를 찾아 기존 상태를 복구한다.

### Scenario 3: 로그인 동기화 병합

- Given 로그인 동기화 사용자의 브라우저 또는 DB에 이름 기반 키가 남아 있다.
- When 로그인 병합, 단건 저장·삭제, 일괄 동기화 또는 조회가 수행된다.
- Then 서버는 구형 바다청소 키를 ID 키로 정규화하고 충돌 시 더 높은 별점을 반환·저장한다.

### Scenario 4: 운영 이름 변경

- Given 바다청소 상태가 ID 키로 저장되어 있다.
- When 관리자가 항목의 `name`을 변경한다.
- Then 렌더링되는 체크리스트 키는 같은 DB ID를 유지하고 사용자 상태가 그대로 표시된다.

## Functional Requirements

- FR-001: 바다청소 일반 키는 `sea_cleaning_id_{id}` 형식이어야 한다.
- FR-002: 바다청소 명인 키는 `mastery_sea_cleaning_id_{id}` 형식이어야 한다.
- FR-003: 기존 행은 전환 직전 이름을 `legacy_checklist_name`에 한 번 저장해야 한다.
- FR-004: 관리자 이름 수정은 `legacy_checklist_name`을 변경하지 않아야 한다.
- FR-005: 서버는 이름 기반 일반·명인 키를 모든 체크리스트 입출력 경계에서 ID 키로 정규화해야 한다.
- FR-006: 로컬 마이그레이션은 렌더링된 레거시 키와 ID 키의 매핑을 사용해야 한다.
- FR-007: 로컬 마이그레이션은 성공한 전체 목록 페이지에서만 버전 `2`를 기록해야 한다.
- FR-008: 다른 도감의 키는 원문 그대로 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 버전 `2`인 브라우저는 로컬스토리지 버전 조회 후 즉시 종료해야 한다.
- NFR-002: 구형 바다청소 키가 없는 서버 요청은 레거시 매핑 DB 조회를 수행하지 않아야 한다.
- NFR-003: 마이그레이션은 재실행해도 값이 손실되지 않아야 한다.

## Edge Cases

- 구형 키와 ID 키가 모두 존재: 큰 별점 값을 보존하고 구형 키를 제거한다.
- 명인 키 충돌: 값 `1`을 보존하고 구형 키를 제거한다.
- 새 항목처럼 레거시 별칭이 없음: ID 키만 사용한다.
- 삭제된 항목의 알 수 없는 구형 키: 임의 변환하거나 삭제하지 않는다.
- 다른 도감의 이름 기반 키: 변경하지 않는다.
- 로컬스토리지 접근 또는 저장 실패: 버전을 올리지 않고 다음 접속 때 재시도한다.

## Data Requirements

- `sea_cleaning_collections.legacy_checklist_name VARCHAR(100) NULL`을 추가한다.
- 기존 행에는 현재 `name`을 레거시 별칭으로 채운다.
- `user_checklist`의 기존 일반·명인 키를 ID 키로 병합한 뒤 구형 키를 삭제한다.
- `legacy_checklist_name`은 최초 전환 후 읽기 전용 데이터로 취급한다.

## Clarifications

- Q: 다른 도감도 함께 ID 키로 전환하는가?
  A: 아니다. 바다청소만 전환한다.
- Q: 이름 변경 때마다 새 별칭을 추가하는가?
  A: 아니다. ID 전환 직전 이름 하나만 보존하면 이후 저장 키는 이름과 무관하다.
- Q: 오래된 마이그레이션 코드를 제거해도 되는가?
  A: 장기 미접속 로컬 데이터를 보존하려면 레거시 정규화는 유지한다.
