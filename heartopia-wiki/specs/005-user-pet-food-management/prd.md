# PRD: 사용자별 반려동물 먹이 관리

## 1. Summary

### Problem

현재 반려동물 화면은 강아지·고양이별 고정 먹이 목록만 제공한다. 사용자가 자신의 반려동물에만 보이는 먹이를 추가하거나, 필요 없는 기본 먹이를 목록에서 제거할 수 없다.

### Proposed Solution

모든 사용자가 선택한 반려동물에 사용자 정의 먹이를 추가하고, 기본 먹이와 사용자 정의 먹이를 삭제할 수 있게 한다. 동기화가 꺼진 데이터는 로그인 여부와 관계없이 같은 브라우저 저장소를 사용하고, 동기화가 켜진 로그인 데이터는 DB에 저장한다. 기본 먹이는 공통 원본에서 삭제하지 않고 반려동물 프로필에서 숨김 처리한다.

### Success Criteria

- 사용자가 선택한 반려동물에 먹이 이름을 추가할 수 있다.
- 추가한 먹이와 삭제한 기본 먹이 상태가 해당 사용자의 기존 펫 먹이 저장 정책에 따라 유지된다.
- 한 브라우저의 추가·삭제 결과가 다른 브라우저에 영향을 주지 않는다.
- 비로그인 사용자도 먹이 추가·삭제 기능을 사용할 수 있다.
- 직접 추가한 이름이 기존 먹이 도감 DB와 일치하면 해당 도감 이미지를 표시한다.

## 2. Users And Use Cases

### Primary Users

- 반려동물 먹이를 기록하는 비로그인·로그인 사용자

### User Stories

- 사용자로서 내 반려동물만을 위한 먹이를 추가하고 싶다.
- 사용자로서 내 반려동물에게 필요 없는 기본 먹이를 목록에서 제거하고 싶다.
- 사용자로서 다른 사람이 수정한 먹이 목록의 영향을 받지 않고 싶다.

## 3. Functional Scope

### In Scope

- 선택된 반려동물의 사용자 정의 먹이 추가
- 기본 먹이와 사용자 정의 먹이 삭제
- 반려동물 프로필 JSON 안에 사용자 정의 먹이와 숨긴 기본 먹이 저장
- 사용자 정의 먹이의 검색·필터·먹여봄·선호도 기록 지원
- 동기화 상태에 따른 저장 위치 분리
- 사용자 정의 먹이 이름과 기존 물고기·요리·채집·작물 DB 데이터의 이미지 매칭
- 삭제한 기본 먹이와 같은 이름을 다시 추가할 때 기본 먹이 복원
- 서버에서 프로필 JSON 구조, 문자열 길이, 항목 개수를 검증

### Out Of Scope

- 공통 기본 먹이 마스터 데이터 변경
- 사용자 간 먹이 공유
- 이미지 업로드 또는 이미지 URL 입력
- 먹이 설명·분류·영양 정보 편집
- 별도 DB 테이블 또는 스키마 마이그레이션

## 4. Acceptance Criteria

- 사용자가 유효한 먹이 이름을 입력하면 현재 반려동물 목록에 즉시 표시된다.
- 빈 이름과 현재 목록에 이미 표시 중인 같은 이름은 등록되지 않는다.
- 기본 먹이를 삭제하면 현재 반려동물에서만 숨겨지고 다른 반려동물과 사용자에게는 계속 표시된다.
- 사용자 정의 먹이를 삭제하면 현재 반려동물 프로필에서 제거되며 관련 먹여봄·선호도 상태도 함께 제거된다.
- 삭제한 기본 먹이와 같은 이름을 추가하면 새 사용자 정의 먹이를 만들지 않고 기본 먹이를 복원한다.
- 비로그인 사용자는 추가 폼과 삭제 버튼을 사용할 수 있고 변경은 공용 브라우저 키에 저장된다.
- 동기화가 켜진 로그인 사용자의 변경은 `/api/user/pet-food`를 통해 해당 사용자 데이터에만 저장된다.
- 동기화가 꺼진 로그인 사용자의 변경은 비로그인과 같은 브라우저 저장소를 사용해 로그인·로그아웃 전후에 이어진다.
- 사용자 정의 먹이 이름이 기존 DB 이름과 공백을 제외하고 일치하면 DB의 이미지 URL을 사용한다.
- 서버는 잘못된 프로필 구조나 허용 범위를 넘는 데이터를 HTTP 400으로 거부하고 DB에 저장하지 않는다.

## 5. Constraints

- Tech: Java 17, Spring Boot, Thymeleaf, Vanilla JS, 기존 `user_pet_food.pets_json`
- Time: 기존 화면과 저장 API를 최소 범위로 확장
- Data: 기존 프로필 JSON과 하위 호환되어야 함
- External Dependencies: 없음

## 6. Risks

- 공용 로컬 저장 키의 계정 데이터 공유: 같은 브라우저에서 동기화를 끈 여러 계정은 기록을 공유한다는 제품 정책으로 허용한다.
- 저장 요청이 비동기라 빠른 연속 변경 시 순서가 뒤바뀔 수 있음: 저장 요청을 순차 처리한다.
- 기본 먹이 ID와 사용자 정의 먹이 ID 충돌: 사용자 정의 ID에 별도 접두사와 난수를 사용한다.
