# PRD: 퍼즐·모래 조각 수집 기록과 메인 진행도

## 1. Summary

### Problem

퍼즐과 모래 조각 페이지에는 보유 여부를 기록할 수단이 없어 사용자가 빠진 항목을 빠르게 찾기 어렵다. 메인 페이지 카드도 전체 데이터 개수만 보여주므로 개인별 수집 진행 상황을 파악할 수 없다.

### Proposed Solution

기존 전역 체크리스트 저장·계정 동기화 구조를 퍼즐과 모래 조각에 확장한다. 메인 페이지에서는 체크 기능을 지원하는 모든 카드에 `완료 수 / 전체 수`를 표시하고, 체크 기능이 없는 카드는 기존 데이터 개수를 유지한다.

### Success Criteria

- 사용자가 퍼즐과 모래 조각을 카드 및 표 보기에서 수집 완료/미완료로 전환할 수 있다.
- 비로그인·동기화 OFF 사용자의 기록은 브라우저에, 동기화 ON 사용자의 기록은 기존 계정 체크리스트에 저장된다.
- 메인 페이지의 모든 체크 지원 카드가 현재 사용자의 정확한 `완료 / 전체`를 표시한다.
- 퍼즐과 모래 조각이 통합 수집 도감의 카테고리와 전체 진행률에 포함된다.

## 2. Users And Use Cases

### Primary Users

- 퍼즐 또는 모래 조각 중 아직 얻지 못한 항목을 확인하려는 방문자
- 여러 기기에서 체크리스트 동기화를 사용하는 로그인 사용자

### User Stories

- As a 수집 사용자, I want to 퍼즐과 모래 조각의 보유 여부를 체크하고 싶다, so that 빠진 항목만 빠르게 찾을 수 있다.
- As a 재방문 사용자, I want to 체크 기록이 기존 방식대로 보존되길 원한다, so that 다시 체크하지 않아도 된다.
- As a 메인 페이지 방문자, I want to 카테고리별 완료 수를 확인하고 싶다, so that 다음에 채울 도감을 바로 선택할 수 있다.

## 3. Functional Scope

### In Scope

- 퍼즐·모래 조각 카드 보기와 표 보기에 체크 UI 추가
- 기존 `ChecklistCore` 및 `/api/user/checklist` 동기화 재사용
- 퍼즐·모래 조각에 ID 기반의 안정적인 체크 키 적용
- 통합 수집 도감에 퍼즐·모래 조각 카테고리 추가
- 메인 페이지의 기존 체크 지원 카테고리와 신규 두 카테고리에 `완료 / 전체` 표시
- 체크 기능이 없는 메인 카드에는 기존 데이터 개수 표시 유지
- 체크 상태 변경 및 계정 데이터 로딩 시 메인 진행도 갱신

### Out Of Scope

- 동물·채집·주민·반려동물 등 현재 체크 기능이 없는 카테고리에 새 체크 기능 추가
- 체크리스트 내보내기·불러오기 기능 구현
- 체크리스트 DB 스키마 변경
- 수집 완료 알림이나 보상 기능

## 4. Acceptance Criteria

- 퍼즐과 모래 조각의 동일 항목이 카드/표 보기에서 같은 체크 키와 상태를 사용한다.
- 체크한 항목은 새로고침 후에도 유지되고, 동기화 ON에서는 기존 계정 동기화 API를 사용한다.
- 신규 키는 항목명이 바뀌어도 유지되도록 각각 `puzzle_id_{id}`, `sandbox_id_{id}` 형식을 사용한다.
- 통합 수집 도감의 전체 개수·완료 개수·퍼센트에 신규 두 카테고리가 포함된다.
- 메인 페이지는 물고기·곤충·새·꽃·작물·요리·바다 청소·업적·퍼즐·모래 조각 진행도를 표시한다.
- 명인용 `mastery_` 키는 완료 개수에 포함하지 않는다.
- 동기화 데이터 로딩 중에는 잘못된 `0 / 전체`를 확정값처럼 깜빡이지 않도록 로딩 상태를 표시한다.
- 체크 기능이 없는 카드는 기존 데이터 개수 문구를 유지한다.

## 5. Constraints

- Tech: Spring Boot, Thymeleaf, Vanilla JS, 기존 `ChecklistCore`/`checklist-sync.js` 구조를 재사용한다.
- Time: 이번 변경은 체크·집계 흐름에 한정한다.
- Data: 퍼즐과 모래 조각의 기존 DB ID를 안정 키로 사용하며 신규 테이블이나 컬럼을 만들지 않는다.
- External Dependencies: 없음.

## 6. Risks

- 카드 보기와 표 보기에서 같은 항목 DOM이 두 번 존재해 완료 수가 중복 집계될 수 있음: 저장 데이터의 고유 키와 서버 전체 개수를 기준으로 집계한다.
- 동기화 ON 메인 페이지에는 현재 체크 DOM이 없어 기존 스크립트가 DB 데이터를 읽지 않음: 전역 데이터 로딩을 UI 존재 여부와 분리한다.
- 일부 카테고리 키가 이름 기반이라 데이터 이름 변경 시 진행도가 어긋날 수 있음: 이번 범위에서는 기존 키 호환성을 유지하고 신규 두 카테고리만 ID 기반으로 시작한다.
- 클라이언트 저장 데이터에 오래된 키가 남아 전체보다 완료가 많아질 수 있음: 현재 카테고리의 유효 키 목록과 교집합으로 완료 수를 계산한다.

## 7. Open Questions

- 없음. 메인 진행도는 모든 체크 지원 카드에 적용하고 비지원 카드는 기존 데이터 개수를 유지하기로 결정했다.
