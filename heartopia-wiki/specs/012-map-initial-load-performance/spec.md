# Feature Spec: 지도 초기 로딩 성능 개선

## Source

- PRD: `specs/012-map-initial-load-performance/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 고래낙하 협곡 첫 진입

- Given 사용자가 `/wiki/map?mapKey=second`에 진입한다
- When 지도 이미지와 초기 데이터를 불러온다
- Then 이미지와 데이터 요청이 병렬로 진행되고 채집물·동물 도감만 요청된다

### Scenario 2: 기본 지도 첫 진입

- Given 사용자가 `/wiki/map` 또는 `/wiki/map?mapKey=town`에 진입한다
- When 지도 초기화가 완료된다
- Then 기존 여섯 도감 종류와 핀·구역 데이터가 모두 반영되고 기존 기본 가시성이 유지된다

### Scenario 3: 지도 딥 링크

- Given 사용자가 카테고리·이름 또는 구역 파라미터가 있는 지도 URL에 진입한다
- When 초기 데이터와 지도 이미지가 준비된다
- Then 해당 항목 정보, 마커 또는 구역 이동이 기존과 동일하게 실행된다

### Scenario 4: 초기 데이터 실패

- Given 필수 지도 API 중 하나가 실패한다
- When 초기화를 시도한다
- Then 불완전한 마커·목록 초기화를 진행하지 않고 오류를 기록한다

## Functional Requirements

- FR-001: 시스템은 지도 이미지와 초기 데이터 요청을 동일한 초기화 단계에서 시작해야 한다.
- FR-002: 시스템은 지도별 지원 도감 카테고리를 설정으로 제공해야 한다.
- FR-003: 기본 지도는 `forageable`, `fish`, `bird`, `insect`, `animal`, `villager` 도감을 요청해야 한다.
- FR-004: 고래낙하 협곡은 `forageable`, `animal` 도감만 요청해야 한다.
- FR-005: 요청하지 않은 도감의 상태 배열은 빈 배열이어야 한다.
- FR-006: 초기 마커와 마스터 데이터가 준비된 뒤 카테고리 목록을 한 번 렌더링해야 한다.
- FR-007: 초기 가시성이 꺼진 핀은 마커 객체만 등록하고 Leaflet 지도 레이어에는 추가하지 않아야 한다.
- FR-008: 기본 지도 서비스 이미지는 원본과 동일한 `1995 × 1998` 해상도의 WebP를 사용해야 한다.
- FR-009: 기존 PNG 원본은 보관해야 한다.
- FR-010: 기존 딥 링크, 구역 라벨, 지도 클릭, 관리자 핀 배치 흐름을 유지해야 한다.
- FR-011: 고래낙하 협곡의 전체 핀·카테고리 기본 표시 정책을 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 이미지 다운로드와 API 왕복 시간이 합산되지 않고 겹쳐야 한다.
- NFR-002: 고래낙하 협곡의 초기 도감 API 호출 수는 2개여야 한다.
- NFR-003: 현재 운영 기본 지도 기준 초기 숨김 핀 333개를 지도 DOM에 붙였다가 제거하는 작업이 없어야 한다.
- NFR-004: 기본 지도 WebP 파일은 1MB 미만이어야 한다.
- NFR-005: API 응답 형식, 데이터베이스 스키마, 보안 정책을 변경하지 않아야 한다.
- NFR-006: 런타임 외부 라이브러리를 추가하지 않아야 한다.

## Edge Cases

- 알 수 없는 `mapKey`는 기존과 같이 `town`으로 정규화된다.
- 활성 지도에 지원 도감 설정이 없으면 기본 지도 설정을 사용한다.
- 핀 또는 구역 배열이 비어 있어도 빈 상태로 정상 초기화한다.
- 고래낙하 협곡에 구역 데이터가 없어도 핀과 도감 목록을 정상 표시한다.
- 이미지 로딩 실패 시 데이터 요청은 이미 시작될 수 있지만 Leaflet 지도 초기화는 진행하지 않는다.

## Data Requirements

- 기존 `map_pins`, `location_zones`, 도감 조회 API를 그대로 사용한다.
- 새 데이터 저장, SQL, 마이그레이션은 없다.
- 지도별 지원 카테고리는 클라이언트 정적 설정으로 관리한다.

## Clarifications

- Q: 성능을 위해 고래낙하 협곡의 전체 표시 기본값을 끌 것인가?
  A: 아니다. 이전 기능 요구사항이므로 유지하고 네트워크 워터폴과 불필요한 요청을 먼저 제거한다.
- Q: 공개 API에 HTTP 캐시를 추가할 것인가?
  A: 아니다. 관리자 변경 직후 반영 정책과 캐시 무효화 설계가 별도로 필요하므로 이번 범위에서 제외한다.
