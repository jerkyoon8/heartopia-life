# Feature Spec: 도감 시간 필터 카드·표 결과 일치

## Source

- PRD: `specs/006-collection-time-filter-table-sync/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 곤충 표 보기 시간 필터

- Given 사용자가 곤충 도감을 표 보기로 열고 날씨 `비`를 선택했다.
- When 등장 시간을 `6~12`로 선택한다.
- Then `0~6 / 18~24` 또는 `0~6 / 12~24`에만 등장하는 곤충은 보이지 않는다.

### Scenario 2: 새 표 보기 시간 필터

- Given 사용자가 새 도감을 표 보기로 열고 날씨 `비`를 선택했다.
- When 등장 시간을 `6~12`로 선택한다.
- Then `12~24`에만 등장하는 새는 보이지 않는다.

### Scenario 3: 보기 방식 전환

- Given 같은 날씨와 시간 필터가 적용되어 있다.
- When 사용자가 카드 보기와 표 보기를 전환한다.
- Then 두 보기의 표시 항목 집합은 동일하다.

## Functional Requirements

- FR-001: 곤충 도감의 각 표 행은 해당 곤충의 등장 시간을 필터가 읽을 수 있는 데이터로 제공해야 한다.
- FR-002: 새 도감의 각 표 행은 해당 새의 등장 시간을 필터가 읽을 수 있는 데이터로 제공해야 한다.
- FR-003: 카드와 표는 동일한 시간 구간 겹침 규칙을 적용해야 한다.
- FR-004: 시간 구간은 반개구간으로 비교하여 `6~12`와 `0~6`, `6~12`와 `12~24`처럼 경계만 맞닿는 경우 겹침으로 처리하지 않아야 한다.
- FR-005: `상시` 항목 포함 여부는 기존 `상시 포함` 선택을 따라야 한다.

## Non-Functional Requirements

- NFR-001: 공통 필터 로직을 복제하지 않고 기존 `WikiFilter`를 사용해야 한다.
- NFR-002: DB 스키마, API 응답, 서버 조회 로직에 영향을 주지 않아야 한다.

## Edge Cases

- 복수 구간(`0~6 / 18~24`)은 각 구간을 독립적으로 비교하고 하나라도 실제로 겹칠 때만 포함한다.
- 시간 값이 `상시`이거나 비어 있으면 기존 `상시 포함` 정책을 유지한다.
- 시작 또는 종료 시간 중 하나만 선택하면 기존처럼 시간 필터를 적용하지 않는다.

## Data Requirements

- 기존 `BugCollection.time`과 `BirdCollection.time` 값을 표 행의 `data-time` 속성에 그대로 렌더링한다.
- 데이터 저장, 조회, 삭제 정책은 변경하지 않는다.

## Clarifications

- Q: 시간 구간 계산 자체도 변경하는가?
  A: 아니다. 현재 공통 필터는 경계만 닿는 구간을 제외하도록 이미 구현되어 있으므로, 누락된 표 행 데이터만 연결한다.

- Q: 카드 보기 결과도 변경하는가?
  A: 아니다. 카드에는 시간 데이터가 이미 연결되어 있어 현재 동작을 유지한다.
