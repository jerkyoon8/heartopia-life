# Feature Spec: 아시아 서버 참여형 시간·날씨 헤더

## Source

- PRD: `specs/015-community-weather-header/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 현재 시간과 날씨 확인

- Given 방문자가 공통 헤더가 있는 페이지를 열었을 때
- When 두 번째 헤더 줄의 오른쪽을 확인하면
- Then 아시아 서버 기준 요일·현재 시각·현재 날씨 또는 상태 문구를 볼 수 있다.

### Scenario 2: 6시간 구간 자동 이동

- Given 현재 아시아 서버 시각이 08시일 때
- When 날씨 상세 패널을 열면
- Then 06–12시부터 다음 날 06–12시까지 연속된 5개 구간이 보인다.
- Given 시각이 12시 경계를 지났을 때
- When 헤더 시계가 갱신되면
- Then 현재 구간을 포함한 5개 상세 구간이 12–18시부터 시작하도록 다시 계산된다.

### Scenario 3: 공개 예보 탐색

- Given 로그인하지 않은 방문자가 날씨 상세 패널을 열었을 때
- When 상세·7일 예보를 확인하면
- Then 상세 예보와 내일부터 시작하는 7일 기본 예보의 합의 날씨, 동점, 미제보 상태와 제보 수를 볼 수 있지만 입력 컨트롤은 사용할 수 없다.

### Scenario 4: 로그인 사용자 배치 제보

- Given 로그인 사용자가 `날씨 제보`를 시작했을 때
- When 알고 있는 상세 구간과 날짜별 기본 날씨를 여러 개 선택하고 `제보 적용하기`를 누르면
- Then 선택한 칸만 한 요청으로 저장되고 선택하지 않은 기존 표는 유지된다.

### Scenario 5: 사용자 제보 수정

- Given 사용자가 이전에 맑음으로 제보한 같은 예보 키가 있을 때
- When 비로 바꾸어 제출하면
- Then 현재 표는 비로 교체되고 맑음에서 비로 바뀐 이력 한 건이 저장된다.

### Scenario 6: 관리자 가중 투표

- Given 일반 사용자 4명이 맑음, 관리자 1명이 비를 선택했을 때
- When 합의 결과를 집계하면
- Then 맑음 4점, 비 5점으로 비가 표시된다.
- Given 이후 맑음 일반표가 6점이 되었을 때
- When 다시 집계하면
- Then 맑음이 표시된다.

### Scenario 7: 동점과 상세·기본 날씨 분리

- Given 상세 구간의 맑음과 비가 같은 최고 점수일 때
- When 합의 결과를 표시하면
- Then `확인 중`을 표시하고 기본 날씨로 덮어쓰지 않는다.
- Given 상세 구간 제보가 전혀 없고 같은 날짜의 기본 날씨만 합의되었을 때
- When 해당 구간을 표시하면
- Then 상세 구간은 `제보 필요`를 유지하고 기본 날씨를 대체값으로 사용하지 않는다.

## Functional Requirements

- FR-001: 시스템은 아시아 서버 시간대를 `Asia/Seoul`로 고정해야 한다.
- FR-002: 헤더 시계는 요일과 `HH:mm` 형식을 표시하고 최소 1분마다 갱신해야 한다.
- FR-003: 시스템은 현재 시각을 포함하는 6시간 구간과 이후 4개 구간을 생성해야 한다.
- FR-004: 시스템은 내일부터 7일 후까지 7개의 날짜별 기본 예보 키를 생성해야 한다.
- FR-005: 날씨 종류는 `SUNNY`, `RAIN`, `RAINBOW`, `METEOR_SHOWER`, `HEATWAVE`만 허용해야 한다.
- FR-006: 상세 예보 키는 날짜와 시작 시각(`0`, `6`, `12`, `18`)으로 식별해야 한다.
- FR-007: 기본 예보 키는 날짜와 고정 슬롯 `-1`로 식별해야 한다.
- FR-008: 공개 조회는 로그인 없이 가능해야 한다.
- FR-009: 제보 제출은 인증된 `CustomOAuth2User`만 가능해야 한다.
- FR-010: 사용자는 예보 키마다 한 표만 가질 수 있고 재제출은 기존 표를 갱신해야 한다.
- FR-011: 한 배치 요청은 일부 또는 여러 상세·기본 예보 표를 포함할 수 있어야 한다.
- FR-012: 제출 시 요청에 없는 예보 키의 사용자 표는 삭제하거나 변경하지 않아야 한다.
- FR-013: 집계는 일반 사용자 표를 1점, 제출 당시 관리자 표를 5점으로 계산해야 한다.
- FR-014: 최고 점수가 하나면 해당 날씨, 둘 이상이면 `TIED`, 표가 없으면 `EMPTY`로 응답해야 한다.
- FR-015: 상세 구간과 날짜별 기본 날씨는 독립적으로 집계하고 서로의 결과로 대체하지 않아야 한다.
- FR-016: 상세 구간이 `EMPTY`이면 같은 날짜의 기본 날씨 존재 여부와 무관하게 `EMPTY`를 유지해야 한다.
- FR-017: 현재 사용자 표를 조회 응답에 포함해 입력 화면에 기존 선택을 복원해야 한다.
- FR-018: 실제 날씨 값이 변경된 수정만 이력에 저장해야 한다.
- FR-019: 7일보다 오래된 변경 이력과 예보 범위 밖의 투표는 정리해야 한다.
- FR-020: 헤더에서 `아이템들`, `기타` 상위 메뉴와 두 메가 메뉴 열을 제거해야 한다.
- FR-021: 참나무·형광석 자원 정보는 렌더링하거나 정적 자원으로 복사하지 않아야 한다.

## Non-Functional Requirements

- NFR-001: 서버는 클라이언트가 보낸 가중치를 신뢰하지 않고 인증 권한에서 직접 계산해야 한다.
- NFR-002: 서버는 날짜·슬롯·날씨 코드·배치 크기를 검증해야 한다.
- NFR-003: 배치 저장과 변경 이력 기록은 하나의 트랜잭션으로 처리해야 한다.
- NFR-004: CSRF 보호를 유지하고 공통 메타 태그의 토큰을 제출 요청에 사용해야 한다.
- NFR-005: 조회 실패 시 헤더 시계는 계속 동작하고 날씨만 `정보 없음` 상태를 표시해야 한다.
- NFR-006: 패널은 키보드로 열고 닫을 수 있으며 Escape 및 바깥 클릭으로 닫혀야 한다.
- NFR-007: 390px 화면에서 가로 스크롤 없이 요약과 제보 화면을 사용할 수 있어야 한다.
- NFR-008: 아이콘은 로컬 WebP로 제공하고 전체 신규 날씨 이미지 용량은 30KB 이하여야 한다.

## Edge Cases

- 자정 경계를 넘는 상세 구간은 올바른 다음 날짜를 사용한다.
- 18–24시는 저장 슬롯 `18`, 화면 종료 라벨 `24`를 사용한다.
- 서버 시각이 정확히 06:00이면 06–12시를 현재 구간으로 판단한다.
- 한 사용자가 같은 예보 키를 배치에 중복 포함하면 요청을 거부한다.
- 허용되지 않은 날씨 코드, 상세 슬롯의 `-1`, 기본 슬롯의 `0/6/12/18`은 거부한다.
- 허용된 날짜 범위 밖의 제보는 거부한다.
- 관리자가 과거 일반 사용자였더라도 새 제출의 가중치는 현재 권한에서 계산한다.
- API 응답 후 6시간 경계를 지나면 클라이언트는 예보를 다시 조회한다.
- 새로 추가된 오른쪽 끝 상세 구간에 시간대 제보가 없으면 같은 날짜의 기본 날씨가 있어도 `제보 필요`로 표시한다.
- 날짜별 기본 예보의 첫 칸은 항상 아시아 서버 기준 내일이며 오늘 날짜의 기본 제보는 허용하지 않는다.

## Data Requirements

- `weather_votes`: 사용자별 현재 표, 날짜, 슬롯, 날씨 코드, 가중치, 생성·수정 시각
- `weather_vote_history`: 값이 실제 변경된 경우 이전·새 날씨와 변경 시각
- `users.id`를 외래 키로 사용하고 사용자 삭제 시 관련 표·이력을 삭제한다.
- 현재 표의 유일 키는 `(user_id, forecast_date, slot_hour)`이다.
- 집계 조회는 `(forecast_date, slot_hour, weather_code)` 인덱스를 사용한다.
- 이력은 `changed_at < NOW() - INTERVAL 7 DAY`, 투표는 `forecast_date < 오늘 - 7일` 또는 예보 범위 만료 기준으로 정리한다.

## Clarifications

- Q: 다른 서버도 선택할 수 있는가?
  A: 아니요. 아시아 서버만 지원하며 서버 선택 UI는 만들지 않는다.
- Q: 관리자가 결과를 강제로 확정할 수 있는가?
  A: 아니요. 관리자는 5점 가중 표를 가지며 일반표가 더 많으면 결과가 바뀐다.
- Q: 상세 예보의 “24시간”은 정확히 현재부터 24시간인가?
  A: 현재가 속한 6시간 구간과 이후 4개 구간이다. 08시 기준 오늘 06–12부터 내일 06–12까지다.
- Q: 2일 이후 상세 시간대도 입력하는가?
  A: 게임이 제공하지 않으므로 입력하지 않는다. 날짜별 기본 날씨만 제공한다.
- Q: 상세 시간대 제보가 없으면 같은 날짜의 기본 날씨로 채우는가?
  A: 아니요. 상세 시간대와 날짜별 기본 날씨는 독립 정보이며 서로 대체하지 않는다.
- Q: 날짜별 기본 예보는 어느 날짜부터 제공하는가?
  A: 오늘은 현재 상세 시간대에서 확인하므로 제외하고, 내일부터 7일 후까지 7칸을 제공한다.
- Q: 다른 팬사이트의 UI나 아이콘을 복사하는가?
  A: 동작 규칙만 참고하고 두두타 도감의 독립 UI와 사용자가 제공한 인게임 아이콘을 사용한다.
