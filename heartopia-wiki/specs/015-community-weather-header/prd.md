# PRD: 아시아 서버 참여형 시간·날씨 헤더

## 1. Summary

### Problem

기존 헤더의 두 번째 줄은 `컬렉션`, `아이템들`, `기타`가 중복된 메가 메뉴를 형성하고 있으며, 접속자 통계를 푸터로 옮긴 뒤 오른쪽 공간이 비어 있다. 게임은 외부 날씨 API를 제공하지 않지만 이용자는 현재 아시아 서버 시간과 날씨, 앞으로 확인 가능한 예보를 빠르게 보고 싶다.

### Proposed Solution

헤더 메뉴를 컬렉션 중심으로 정리하고, 두 번째 줄 오른쪽에 아시아 서버 요일·시간·현재 날씨를 표시한다. 로그인 사용자가 6시간 구간별 상세 예보와 날짜별 기본 날씨를 배치로 제보하며, 일반 사용자 1표·관리자 5표의 가중 합의 결과를 모든 방문자에게 제공한다.

### Success Criteria

- 헤더에서 아시아 서버 기준 요일·시각·현재 날씨를 페이지 이동 없이 확인할 수 있다.
- 현재가 속한 6시간 구간과 이후 4개 구간, 총 5개 상세 예보가 자동으로 이동한다.
- 내일부터 7일 후까지의 날짜별 기본 날씨를 확인하고 로그인 사용자는 여러 칸을 한 번에 제보할 수 있다.
- 동점·미제보 상태를 임의의 날씨로 확정하지 않고 명확하게 표시한다.
- 헤더에서 `아이템들`, `기타` 메뉴와 메가 메뉴 열이 제거되고 컬렉션 메뉴만 남는다.

## 2. Users And Use Cases

### Primary Users

- 아시아 서버에서 플레이하는 비로그인·로그인 방문자
- 날씨 예보를 공유하고 정정하는 로그인 사용자
- 일반 사용자보다 높은 가중치로 의견을 보완하는 관리자

### User Stories

- As a 방문자, I want to 헤더에서 서버 시간과 현재 날씨를 확인, so that 게임을 열지 않고도 현재 상태를 파악할 수 있다.
- As a 방문자, I want to 헤더 날씨를 눌러 앞으로의 5개 상세 구간과 7일 기본 예보를 확인, so that 수집 활동을 계획할 수 있다.
- As a 로그인 사용자, I want to 내가 아는 여러 예보 칸을 선택한 뒤 한 번에 제출, so that 반복 요청 없이 정보를 공유할 수 있다.
- As a 로그인 사용자, I want to 내 기존 제보를 수정, so that 잘못 입력한 정보를 바로잡을 수 있다.
- As a 관리자, I want to 일반 사용자 5명에 해당하는 표로 참여, so that 테러성 제보를 완화하되 관리자도 틀릴 수 있는 여지를 유지할 수 있다.

## 3. Functional Scope

### In Scope

- 아시아 서버(`Asia/Seoul`, UTC+9) 요일·현재 시각 표시
- 맑음, 비, 무지개, 유성우, 폭염의 인게임 아이콘 적용
- 현재 6시간 구간과 이후 4개 구간의 상세 예보
- 내일부터 7일 후까지의 날짜별 기본 날씨
- 상세 시간대와 날짜별 기본 날씨를 서로 대체하지 않는 독립 표시 규칙
- 공개 예보 조회 API
- 로그인 사용자 전용 배치 제보 API
- 일반 사용자 가중치 1, 관리자 가중치 5
- 사용자별 시간대·날짜별 1표 및 기존 표 수정
- 동점 `확인 중`, 미제보 `제보 필요` 표시
- 변경 이력과 만료 데이터 7일 보관
- 헤더의 `아이템들`, `기타` 메뉴 및 해당 메가 메뉴 열 제거
- 밝은/어두운 테마 및 모바일 대응

### Out Of Scope

- 글로벌, 아메리카, SEA 등 다른 서버 지원
- 외부 날씨 API 또는 다른 팬사이트 API 연동
- 참나무·형광석 등 자원 생성 정보
- 관리자 강제 확정 또는 예보 잠금
- 2일 이후 시간대별 상세 예보
- 다른 사이트의 UI, 코드, 이미지 파일 복제

## 4. Acceptance Criteria

- 현재 시각이 08시라면 `오늘 06–12`, `12–18`, `18–24`, `내일 00–06`, `내일 06–12`가 상세 예보에 나타난다.
- 12시가 되면 첫 구간이 `오늘 12–18`로 자동 이동한다.
- 헤더 날씨 요약은 현재 상세 구간의 합의 결과만 사용하며, 상세 제보가 없으면 `제보 필요`를 표시한다.
- 같은 최고 가중치가 둘 이상이면 날씨를 선택하지 않고 `확인 중`을 표시한다.
- 제보가 전혀 없으면 `제보 필요`를 표시한다.
- 비로그인은 예보를 볼 수 있지만 제출 API는 사용할 수 없다.
- 로그인 사용자는 각 예보 키에 한 표만 가지며 재제출은 기존 표를 교체한다.
- 관리자 한 명의 표는 집계 시 5표로 계산되며 다른 사용자 6표 이상으로 뒤집힐 수 있다.
- 배치 제출에서 선택하지 않은 칸은 기존 사용자 표를 변경하지 않는다.
- 실제 날씨 선택 변경만 이력으로 남고 7일보다 오래된 이력·만료 예보는 삭제된다.
- 모바일 헤더에서는 시간·날씨 요약이 잘리지 않고 상세 패널이 화면 너비 안에 표시된다.

## 5. Constraints

- Tech: Java 17, Spring Boot 3.4.2, Spring Security, Thymeleaf, Vanilla JS, MyBatis, MySQL 8.0
- Time: 6시간 경계는 `00`, `06`, `12`, `18`시이며 아시아 서버 시각만 사용
- Data: SQL 자동 초기화가 꺼져 있으므로 신규 테이블 SQL은 배포 전에 별도 실행 필요
- External Dependencies: 사용자가 제공한 로컬 WebP 아이콘 5개 외에 신규 외부 의존성 없음

## 6. Risks

- 소수 또는 악성 사용자가 결과를 왜곡할 수 있음: 로그인 1인 1표, 관리자 5표, 동점 미확정, 수정 이력으로 완화한다.
- 사용자 기기 시각이 틀릴 수 있음: 표시 시각은 `Asia/Seoul`로 계산하되 서버 API 응답 시각을 기준점으로 사용한다.
- 상세 예보와 기본 날씨가 충돌할 수 있음: 두 예보를 독립적으로 표시하고 서로의 빈칸을 대체하지 않는다.
- 헤더가 복잡해질 수 있음: 평상시에는 한 줄 요약만 보이고 상세 확인·제보는 확장 패널에서 처리한다.
- DB 테이블 미적용 시 기능이 실패함: 배포 전 SQL 실행과 검증 쿼리를 필수 후속 조치로 안내한다.
