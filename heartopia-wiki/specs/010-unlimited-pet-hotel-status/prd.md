# PRD: 반려동물 호텔 체크 개수 제한 제거

## 1. Summary

### Problem

위키 계정 하나를 여러 사람이 사용하거나 여러 게임 캐릭터의 기록을 함께 관리할 수 있어, 게임 캐릭터 한 명 기준의 호텔 정원 5마리를 위키 저장 제한으로 강제하면 정상적인 기록을 막을 수 있다.

### Proposed Solution

호텔 체크 개수 제한은 제거하되, 각 프로필의 `inHotel` 값이 불리언인지 확인하는 서버 검증은 유지한다. 게임 내 캐릭터당 정원 5마리는 화면에 안내 정보로만 제공한다.

### Success Criteria

- 호텔 상태가 체크된 반려동물이 6마리 이상이어도 저장된다.
- `inHotel`에 문자열이나 숫자 등 잘못된 값이 들어오면 서버가 거부한다.
- 기존 호텔 강조 표시와 체크 해제 기능이 그대로 동작한다.

## 2. Users And Use Cases

### Primary Users

- 하나의 위키 계정으로 여러 사람 또는 여러 캐릭터의 반려동물 기록을 관리하는 사용자

### User Stories

- As a 공동 계정 사용자, I want to 호텔 체크 개수와 관계없이 상태를 기록하고, so that 여러 캐릭터의 반려동물을 빠짐없이 관리할 수 있다.

## 3. Functional Scope

### In Scope

- 클라이언트의 호텔 5마리 차단 로직 제거
- 서버의 호텔 체크 개수 제한 제거
- `inHotel` 불리언 타입 검증 유지
- 게임 내 캐릭터당 정원 5마리 안내 표시
- 관련 서비스 및 템플릿 테스트 수정

### Out Of Scope

- 사용자별·캐릭터별 하위 프로필 기능
- 전체 반려동물 최대 20마리 제한 제거
- 호텔 입실 날짜나 객실 정보 추가

## 4. Acceptance Criteria

- 호텔 상태가 `true`인 프로필 20개가 서버 검증을 통과한다.
- `inHotel: "true"`는 기존과 같이 검증 오류가 발생한다.
- 화면에서 여섯 번째 호텔 체크를 막거나 오류 메시지를 표시하지 않는다.
- 게임 내 정원 안내는 저장 제한이 아니라는 의미로 표시된다.

## 5. Constraints

- Tech: 기존 JSON 배열 저장, Vanilla JavaScript, Spring 서비스 검증
- Time: 현재 작업에서 구현 및 회귀 테스트 완료
- Data: 프로필 객체의 `inHotel` 불리언 필드 유지
- External Dependencies: 없음

## 6. Risks

- 사용자가 실제 게임 정원도 무제한으로 오해할 수 있음: 캐릭터당 5마리라는 안내 문구를 함께 표시한다.
- 검증 제거 범위가 넓어질 수 있음: 개수 검증만 제거하고 타입·필드·프로필 수 검증은 유지한다.

## 7. Open Questions

- 없음. 사용자가 개수 제한 제거와 유효성 검증 유지를 명시했다.
