# PRD: 빙설 시즌 도감 데이터 추가

## 1. Summary

### Problem

첫 이벤트인 `빙설 시즌`의 작물, 꽃, 요리, 새, 곤충, 물고기가 현재 도감에 없어 사용자가 전체 이벤트 수집품과 등급별 판매가를 확인할 수 없다.

### Proposed Solution

취미 `눈 조각`을 제외한 27종을 기존 도감 테이블에 추가하고, 각 항목의 이미지와 현재 도감이 지원하는 상세 정보 및 1성부터 5성까지의 판매가를 함께 제공한다.

### Success Criteria

- 작물 1종, 꽃 1종, 요리 10종, 새 5종, 곤충 5종, 물고기 5종이 `빙설 시즌` 이벤트로 조회된다.
- 27종 모두 1~5성 판매가와 로컬 정적 이미지가 표시된다.
- 요리 10종은 재료 구성과 요구 수량을 확인할 수 있다.

## 2. Users And Use Cases

### Primary Users

- 빙설 시즌 도감과 수집 현황을 관리하는 위키 사용자

### User Stories

- As a 위키 사용자, I want to 빙설 시즌 항목을 종류별 도감에서 확인하고, so that 수집 여부와 판매 가치를 한곳에서 관리할 수 있다.

## 3. Functional Scope

### In Scope

- 무, 히말라야양귀비 데이터
- 빙설 시즌 요리 10종과 재료 데이터
- 겨울 옷 새 5종
- 얼음 결정 곤충 5종
- 얼음 결정 물고기 5종
- 27종의 1~5성 판매가와 로컬 WebP 이미지
- 반복 실행 가능한 MySQL 8 데이터 반영 SQL

### Out Of Scope

- 취미 `눈 조각`
- 기존 도감에 없는 요리 체력 회복량 필드 신설
- 히말라야양귀비의 색상별 교배 규칙과 변종 이미지
- 운영 DB 실행, 배포 및 Git push

## 4. Acceptance Criteria

- SQL 실행 후 각 대상 테이블의 빙설 시즌 행 수가 각각 1/1/10/5/5/5이다.
- 이름, 레벨, 장소, 시간, 날씨, 크기·종류, 성장 시간, 씨앗 구매가, 재료 등 기존 도감 필드에 대응하는 원본 정보가 저장된다.
- 제공 사이트에서 확인한 등급 배율을 적용한 가격과 사용자가 확정한 히말라야양귀비 가격이 저장된다.
- SQL을 다시 실행해도 대상 이름의 중복 행이 생기지 않는다.
- 모든 `image_url`이 저장소에 포함된 WebP 파일을 가리킨다.

## 5. Constraints

- Tech: Java 17, Spring Boot, MyBatis, MySQL 8.0, Thymeleaf
- Time: 현재 작업에서 구현 및 자동 검증까지 완료
- Data: 제공 사이트의 빙설 시즌 JSON·이미지를 우선 사용하고, 히말라야양귀비는 사용자가 확정한 수치와 제공한 WebP를 사용
- External Dependencies: 제공 사이트 저장소, 사용자 제공 꽃 이미지

## 6. Risks

- 제공 사이트의 새 가격은 2성 기준이다: 사이트 계산 규칙에 따라 1성과 3~5성을 변환하고 테스트로 고정한다.
- 기존 작업 트리가 수정된 상태다: 기존 수정 파일을 건드리지 않고 신규 SQL·이미지·테스트·명세 중심으로 구현한다.
- Spring SQL 자동 초기화가 꺼져 있다: 배포와 별도로 SQL 실행이 필요함을 인계한다.

## 7. Open Questions

- 없음. 히말라야양귀비의 성장 시간, 씨앗 구매가, 1~5성 판매가와 이미지 경로는 사용자 답변으로 확정됐다.
