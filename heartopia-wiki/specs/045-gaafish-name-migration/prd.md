# PRD: 동갈치 → 가아피쉬 단독 마이그레이션

## Summary

운영 물고기·요리·체크리스트·펫 먹이 데이터에 잘못된 명칭 `동갈치`가 남아 있다. 이미지 URL과 실제 파일은 유지하고, 도감 데이터와 로그인 사용자의 상태는 운영 DB에서 직접 변경한다. 비로그인 또는 동기화 OFF 사용자의 상태는 버전 기반 localStorage 마이그레이션으로 한 번만 변경한다. 영구적인 서버 별칭 계층은 추가하지 않는다.

## Success Criteria

- 표시 데이터에서 `동갈치`가 제거되고 정해진 `가아피쉬` 이름이 존재한다.
- 체크리스트 317행·60명의 별점과 펫 먹이 프로필 1행의 설정이 보존된다.
- 비로그인 및 동기화 OFF 사용자의 체크리스트·펫 먹이 localStorage가 이관된다.
- 로그인 및 동기화 ON 사용자의 체크리스트·펫 먹이 DB 데이터가 이관된다.
- 물고기·요리 이미지 URL 9개와 실제 파일은 변경되지 않는다.

## In Scope

- 물고기 4종 이름
- 수프 5종의 요리명과 재료 문자열
- `user_checklist`의 일반·명인 체크 키
- `user_pet_food.pets_json`의 해당 `customFoods[].name`
- `heartopia_checklist`와 `heartopia_pet_food_profiles`의 버전 기반 로컬 이관
- 운영 캐시 교체와 사후 잔여 데이터 검증

## Out Of Scope

- `fish_collections.image_url` 4건과 `cooking_collections.image_url` 5건
- 실제 업로드 파일명 또는 파일 이동
- 영구적인 서버 별칭·요청 정규화 계층
- 옛 상세 URL 리다이렉트
- `동갈치`와 무관한 변경

## Acceptance Criteria

- 대상 신명칭 충돌이 없고 대상 ID·구명칭이 일치할 때만 SQL을 실행한다.
- 체크리스트 구키와 새키가 충돌하면 높은 별점을 보존하고 구키를 제거한다.
- 로컬 이관은 로그인 시 체크리스트를 서버에 병합하는 코드보다 먼저 실행한다.
- 펫 먹이 이름 변경 시 선호도·먹여봄·숨김 등 기존 상태를 보존한다.
- 오래 열린 구버전 탭을 고려해 배포 후 잔여 구명칭 정리 SQL을 한 번 더 실행한다.
- 이미지 URL은 UPDATE 대상에서 제외하고 전후 동일성을 검증한다.

## Confirmed Decisions

- 이미지 경로와 파일명은 그대로 둔다.
- 비로그인/동기화 OFF 데이터는 localStorage 버전 마이그레이션으로 처리한다.
- 로그인/동기화 ON 데이터는 운영 DB를 직접 변경한다.
- 펫 먹이 이름도 변경 범위에 포함한다.
- 상시 유지해야 하는 서버 호환 별칭은 만들지 않는다.

## Risks

- 로그인 직전 구 localStorage 재유입: 로컬 변환을 로그인 병합보다 먼저 실행한다.
- 열린 구버전 탭의 늦은 저장: 전환 뒤 관찰 후 동일한 멱등 SQL로 잔여분을 재정리한다.
- 키 충돌: DB와 localStorage 모두 높은 별점을 보존한다.
- 캐시 불일치: 카탈로그 변경 뒤 새 컨테이너를 기동해 새 데이터로 캐시를 채운다.
- 내부 이미지 경로에는 의도적으로 `동갈치` 문자열이 남는다.
