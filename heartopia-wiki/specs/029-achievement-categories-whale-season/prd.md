# PRD: 업적 카테고리 관리와 고래 시즌 업적 추가

## 1. Summary

### Problem

업적 관리자 모달에 카테고리 입력 항목이 없어 새 업적을 저장하면 필수 컬럼인 `categories`를 설정할 수 없다. 또한 고래 시즌의 바다 청소 업적 4개와 신규 카테고리 두 종류가 서비스 데이터에 없다.

### Proposed Solution

업적 추가·수정 모달에 기존 및 신규 카테고리를 선택할 수 있는 입력을 제공하고, 공개 업적 필터에도 `바다 청소`, `숨바꼭질 파티`를 노출한다. 제공된 `info.txt`와 이미지 4개를 정리한 배포용 SQL 및 정적 이미지로 추가한다.

### Success Criteria

- 관리자가 업적 추가 또는 수정 시 카테고리를 한 개 이상 선택해 저장할 수 있다.
- 공개 업적 페이지에서 `바다 청소`와 `숨바꼭질 파티` 카테고리를 필터링할 수 있다.
- 바다 청소 업적 4개의 이름, 조건, 칭호, 이미지가 제공 자료와 일치하고 보충 설명은 팁으로 표시된다.

## 2. Users And Use Cases

### Primary Users

- 업적 데이터를 관리하는 관리자
- 업적 조건과 획득 팁을 조회하는 일반 사용자

### User Stories

- As a 관리자, I want to 업적의 카테고리를 선택하고 수정할 수 있어야 한다, so that 새 데이터를 올바른 분류로 등록할 수 있다.
- As a 사용자, I want to 바다 청소 업적을 필터링하고 상세 팁을 확인하고 싶다, so that 달성 방법을 쉽게 이해할 수 있다.

## 3. Functional Scope

### In Scope

- 업적 관리자 모달의 다중 카테고리 선택 및 필수 검증
- 수정 모달에서 기존 카테고리, 팁, 정렬 순서 복원
- 공개 필터에 `바다 청소`, `숨바꼭질 파티` 추가
- 고래 시즌 바다 청소 업적 4개용 멱등 SQL 및 이미지 추가
- 템플릿과 SQL 회귀 테스트

### Out Of Scope

- 별도 카테고리 테이블 또는 카테고리 CRUD 화면 도입
- `숨바꼭질 파티` 업적 데이터 생성(제공 원본 없음)
- 운영 DB에 직접 SQL 실행 또는 배포

## 4. Acceptance Criteria

- 카테고리를 선택하지 않으면 브라우저 기본 검증으로 업적 폼을 제출할 수 없다.
- 여러 카테고리를 선택하면 기존 DB 형식인 쉼표 구분 문자열로 바인딩된다.
- 수정 버튼을 누르면 기존 카테고리와 팁, 정렬 순서가 폼에 채워진다.
- 네 업적은 `바다 청소` 카테고리와 59~62 정렬 순서를 가지며 이름 충돌 시 안전하게 갱신된다.
- `넘실대는 해류`의 `/` 뒤 설명은 슬래시 없이 자연스러운 팁 문장으로 저장된다.
- 이미지 URL과 실제 정적 파일 이름이 일치한다.

## 5. Constraints

- Tech: Spring Boot, Thymeleaf, MyBatis, MySQL 8.0, Vanilla JS의 기존 구조 유지
- Time: 현재 작업 범위에서 구현 및 자동 테스트까지 완료
- Data: `C:\Users\k\Desktop\user_kit\고래시즌\업적\info.txt`와 동봉 이미지 기준
- External Dependencies: 운영 반영 시 SQL 실행 필요

## 6. Risks

- 원본의 `바다 정화 전문가`와 이미지 파일 `바다청소전문가.webp` 이름 불일치: 업적 이름을 기준으로 이미지를 `바다 정화 전문가.webp`로 복사해 URL을 일치시킨다.
- 수동 JSON 문자열에 특수문자가 포함될 수 있음: 기존 편집 데이터 전달 방식을 유지하되 필요한 필드를 테스트로 검증한다.
- 운영 DB의 기존 동명 데이터: `ON DUPLICATE KEY UPDATE`로 정정 가능한 멱등 SQL을 사용한다.
