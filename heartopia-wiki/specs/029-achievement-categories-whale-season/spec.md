# Feature Spec: 업적 카테고리 관리와 고래 시즌 업적 추가

## Source

- PRD: `specs/029-achievement-categories-whale-season/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 카테고리를 지정해 업적 추가

- Given 관리자가 업적 페이지의 추가 모달을 열었다
- When 하나 이상의 카테고리와 필수 업적 정보를 입력해 제출한다
- Then 선택한 카테고리가 쉼표 구분 값으로 저장되고 업적 목록에서 필터링된다

### Scenario 2: 기존 업적 수정

- Given 카테고리와 팁이 있는 기존 업적이 보인다
- When 관리자가 수정 버튼을 누른다
- Then 기존 카테고리, 이름, 칭호, 조건, 팁, 정렬 순서와 이미지 상태가 수정 폼에 복원된다

### Scenario 3: 바다 청소 업적 조회

- Given 배포용 SQL과 정적 이미지가 운영 환경에 반영되었다
- When 사용자가 `바다 청소` 필터를 선택하거나 신규 업적 상세를 연다
- Then 해당하는 4개 업적만 분류되고 조건, 칭호, 이미지 및 존재하는 팁이 표시된다

### Scenario 4: 숨바꼭질 파티 카테고리 사용

- Given 관리자가 향후 숨바꼭질 파티 업적을 등록한다
- When `숨바꼭질 파티` 카테고리를 선택해 저장한다
- Then 공개 업적 페이지의 동일 카테고리 필터에서 해당 업적을 찾을 수 있다

## Functional Requirements

- FR-001: 시스템은 업적 추가·수정 폼에 낚시, 요리, 새 관찰, 곤충 채집, 원예, 고양이/강아지, 생활, 이벤트, 숨겨진, 바다 청소, 숨바꼭질 파티 선택지를 제공해야 한다.
- FR-002: 시스템은 업적마다 하나 이상의 카테고리를 선택하도록 요구해야 하며 다중 선택을 허용해야 한다.
- FR-003: 시스템은 수정 폼에서 저장된 쉼표 구분 카테고리를 개별 선택 상태로 복원해야 한다.
- FR-004: 시스템은 팁과 0 이상의 정렬 순서를 추가·수정할 수 있어야 하며, 정렬 순서가 전달되지 않으면 0을 사용해야 한다.
- FR-005: 시스템은 공개 필터에 신규 카테고리 두 개를 제공해야 한다.
- FR-006: 배포용 SQL은 제공된 네 업적을 삽입하고 동명 행이 있으면 제공 자료 기준으로 갱신해야 한다.
- FR-007: 시스템은 네 업적의 이미지 URL과 실제 정적 파일을 일치시켜야 한다.

## Non-Functional Requirements

- NFR-001: 카테고리 저장 형식과 DB 스키마는 기존 쉼표 구분 `VARCHAR(100)` 방식을 유지한다.
- NFR-002: 관리자 기능은 기존 Spring Security의 `ADMIN` 권한 경계를 유지한다.
- NFR-003: SQL은 MySQL 8.0에서 반복 실행해도 중복 행을 만들지 않아야 한다.
- NFR-004: 카테고리 선택지는 작은 화면에서도 줄바꿈되어 읽고 누를 수 있어야 한다.

## Edge Cases

- 카테고리 미선택: 폼 제출을 막고 선택을 요구한다.
- 다중 카테고리: 동일한 `name=categories` 값을 여러 개 전송하면 Spring 바인딩 결과가 기존 쉼표 구분 형식과 호환되어야 한다.
- 팁 없음: 빈 문자열 또는 `NULL`을 허용하고 상세 페이지의 팁 영역을 표시하지 않는다.
- 정렬 순서 없음 또는 음수: 누락 값은 0으로 정규화하고 음수 값은 거부한다.
- 원본 이미지 이름 불일치: `바다 정화 전문가` 업적 이름에 맞춘 파일명을 저장한다.
- 빈 `숨바꼭질 파티` 결과: 필터 선택 시 기존의 검색 결과 없음 상태를 표시한다.

## Data Requirements

- `넘실대는 해류`: 조건 `임의 해저 메사의 생태 어군 레벨이 '넘실대는 해류' 달성`, 칭호 `밀집`, 팁 `바다 청소 취미 5레벨에 열리는 바다집(해저 메사)에서 생태 어군 25레벨을 달성하면 획득할 수 있습니다.`
- `사각지대 없음`: 조건 `바다 청소 사건의 숨겨진 단계를 누적 10회 발동한다.`, 칭호 `비경`
- `자격증 취득`: 조건 `바다 청소 사건에서 거대 오염물 제거 누적 60회 참여한다.`, 칭호 `장애물 제거`
- `바다 정화 전문가`: 조건 `바다 청소 취미 10레벨 달성`, 칭호 `바다`
- 네 데이터의 카테고리는 `바다 청소`, 정렬 순서는 59~62로 저장한다.

## Clarifications

- Q: 원본의 `/`로 시작하는 문장은 어디에 노출하는가?
  A: 달성 조건을 보충하는 사용자 설명이므로 슬래시를 제거하고 자연스럽게 다듬어 `tip`에 저장한다.
- Q: `숨바꼭질 파티` 원본 업적이 없는 경우 어떻게 하는가?
  A: 신규 카테고리로 등록·필터링할 수 있게만 하고 추정 데이터를 생성하지 않는다.
