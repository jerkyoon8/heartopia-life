# Feature Spec: 반려동물 표시 순서 조정

## Source

- PRD: `specs/009-pet-display-order/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 선택한 반려동물을 왼쪽으로 이동

- Given 선택한 반려동물 앞에 다른 반려동물이 있다.
- When 사용자가 `왼쪽 이동` 버튼을 누른다.
- Then 두 반려동물의 배열 위치가 바뀌고 선택한 반려동물이 한 칸 왼쪽에 표시된다.

### Scenario 2: 선택한 반려동물을 오른쪽으로 이동

- Given 선택한 반려동물 뒤에 다른 반려동물이 있다.
- When 사용자가 `오른쪽 이동` 버튼을 누른다.
- Then 두 반려동물의 배열 위치가 바뀌고 선택한 반려동물이 한 칸 오른쪽에 표시된다.

### Scenario 3: 순서 유지

- Given 사용자가 반려동물 순서를 변경했다.
- When 페이지를 새로고침하거나 로그인 동기화 데이터를 다시 불러온다.
- Then 마지막으로 저장한 배열 순서로 반려동물이 표시된다.

## Functional Requirements

- FR-001: 선택 상세 영역에 `왼쪽 이동`, `오른쪽 이동` 버튼을 제공해야 한다.
- FR-002: 이동 함수는 선택 ID의 배열 인덱스와 인접 인덱스를 교환해야 한다.
- FR-003: 이동 후 `selectedPetId`를 변경하지 않아야 한다.
- FR-004: 이동 후 기존 `saveProfiles()`와 `render()`를 호출해야 한다.
- FR-005: 선택 항목이 첫 번째이면 왼쪽 버튼, 마지막이면 오른쪽 버튼을 비활성화해야 한다.
- FR-006: 항목이 하나뿐이면 양쪽 버튼을 모두 비활성화해야 한다.

## Non-Functional Requirements

- NFR-001: 버튼은 `type="button"`, 명확한 텍스트 및 `title`을 제공해야 한다.
- NFR-002: 기존 이름 수정, 호텔 상태, 삭제 기능과 시각적으로 구분되면서 모바일에서 줄바꿈되어야 한다.
- NFR-003: DB 스키마나 API payload 필드를 추가하지 않아야 한다.

## Edge Cases

- 선택 ID가 배열에 없으면 이동하지 않는다.
- 목표 인덱스가 배열 범위를 벗어나면 이동·저장·렌더링을 하지 않는다.
- 서버 동기화 저장 중 추가 이동이 발생하면 기존 `saveQueue`가 요청 순서를 보장한다.

## Data Requirements

- `state.pets` JSON 배열의 요소 순서가 표시 순서이자 저장 순서다.
- 기존 프로필 객체 구조는 변경하지 않는다.

## Clarifications

- Q: 좌우 이동은 화면에 보이는 순서만 바꾸는가?
  A: 그렇다. 반려동물 데이터와 호텔 상태는 그대로 두고 배열 위치만 바꾼다.
- Q: 드래그 정렬도 필요한가?
  A: 이번 범위에는 포함하지 않고 명시적으로 요청한 좌우 이동 버튼만 제공한다.
