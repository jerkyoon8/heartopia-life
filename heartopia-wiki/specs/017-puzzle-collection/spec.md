# Feature Spec: 퍼즐 도감

## Source

- PRD: `specs/017-puzzle-collection/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 퍼즐 전체 목록 확인

- Given 퍼즐 도감 데이터와 이미지가 로컬 DB·정적 리소스에 반영되어 있다.
- When 이용자가 `/wiki/others/puzzles`를 연다.
- Then 도감순으로 정렬된 퍼즐 90개와 이미지·이름·분류·크기·획득처·구매가격이 표시된다.

### Scenario 2: 이름으로 퍼즐 검색

- Given 퍼즐 목록이 표시되어 있다.
- When 이용자가 검색창에 한국어 이름 일부를 입력한다.
- Then 해당 문자열을 포함하는 퍼즐만 즉시 남는다.

### Scenario 3: 분류와 크기로 필터

- Given 일반·동물 퍼즐과 1x1~4x4 크기의 퍼즐이 섞여 있다.
- When 이용자가 분류 또는 크기 필터를 선택한다.
- Then 선택 조건을 모두 만족하는 퍼즐만 표시되고 결과 수가 갱신된다.

### Scenario 4: 기타 정보에서 진입

- Given 이용자가 메인 위키 또는 헤더 메뉴를 보고 있다.
- When 퍼즐 링크를 선택한다.
- Then `/wiki/others/puzzles`로 이동한다.

## Functional Requirements

- FR-001: 시스템은 이미지가 확보된 퍼즐 항목 90개만 퍼즐 데이터로 저장해야 한다.
- FR-002: 시스템은 `image_id`, `catalog_order`, `category`, `name`, `size`, `acquisition_method`, `purchase_price`, `image_url`, `sort_order`를 보존해야 한다.
- FR-003: 시스템은 퍼즐 목록을 `sort_order` 오름차순으로 조회해야 한다.
- FR-004: 목록 화면은 이미지, 한국어 이름, 분류, 크기, 획득처, 구매가격을 표시해야 한다.
- FR-005: 목록 화면은 이름 검색, 분류 필터, 크기 필터를 제공해야 한다.
- FR-005-A: 필터 UI는 물고기 도감의 기본 검색줄·상세 옵션·조건 검색·정렬 및 보기 전환 구조를 따라야 한다.
- FR-006: 필터 결과가 없으면 빈 결과 안내를 표시해야 한다.
- FR-007: 메인 기타 정보 카드와 헤더 기타정보 목록에 퍼즐 링크를 추가해야 한다.
- FR-008: 메인 기타 정보 카드에는 실제 퍼즐 데이터 개수를 표시해야 한다.

## Non-Functional Requirements

- NFR-001: 이미지에는 lazy loading과 대체 텍스트를 적용한다.
- NFR-002: 모바일에서는 카드가 한 열로 줄어들고 필터 조작이 가능해야 한다.
- NFR-003: 기존 라이트·다크 테마 변수와 공통 헤더·푸터를 사용한다.
- NFR-004: 목록 조회는 한 번의 DB 쿼리로 완료되어야 한다.
- NFR-005: SQL은 MySQL 8.0에서 재실행 가능한 upsert 형태여야 한다.

## Edge Cases

- 구매가격이 비어 있으면 `-`로 표시한다.
- 이미지가 없는 엑셀 57~58번, 83~98번은 목록에 포함하지 않는다.
- 이미지 로딩이 실패해도 카드의 텍스트 정보는 유지한다.
- 검색어 앞뒤 공백과 영문 대소문자는 필터 결과에 영향을 주지 않는다.
- 분류와 크기 필터를 동시에 적용하면 AND 조건으로 처리한다.

## Data Requirements

- 입력 기준: `두근두근타운-퍼즐.xlsx`의 `퍼즐` 시트
- 이미지 기준: 기존 `puzzle_images/images` WebP 80개와 `고래탐사시즌_퍼즐_10종/완성본` WebP 10개
- 저장: `puzzle_collections` 테이블
- 조회: 공개 목록 페이지에서 전체 조회
- 삭제: 이번 범위에는 관리자 삭제 기능을 제공하지 않는다.
- 매칭:
  - 이미지 1~56 ↔ 엑셀 도감순 1~56
  - 이미지 57~80 ↔ 엑셀 도감순 59~82
  - 고래 탐사 시즌 이미지 10개 ↔ 엑셀 도감순 99~108

## Clarifications

- Q: 엑셀의 108개를 모두 노출하는가?
  A: 아니다. 현재 이미지까지 연결 가능한 90개만 노출한다.
- Q: “대충 데이터”는 샘플 몇 건만 의미하는가?
  A: 확보한 데이터가 구조화되어 있으므로 이미지와 검증된 90개 전체를 로컬 초기 데이터로 사용한다.
- Q: 고래 탐사 시즌 퍼즐을 별도 이벤트 필드로 구분하는가?
  A: 아니다. 사용자 최종 결정에 따라 분류 자체를 `고래 탐사 시즌`으로 저장한다.

## Whale Category Requirements

- FR-009: 99~108번 퍼즐의 `category`는 `고래 탐사 시즌`이어야 한다.
- FR-010: 퍼즐 카드와 표는 기존 분류 위치에 `고래 탐사 시즌`을 표시해야 한다.
- FR-011: 기존 분류 필터에 `고래 탐사 시즌` 선택지를 제공해야 한다.
- FR-012: 99~108번은 획득처 `고래 탐사 시즌-트렌드 상점`과 `3,760 토큰` 또는 `1,200 토큰` 가격을 가져야 한다.
- AC-009: `category='시즌한정'`인 퍼즐이 0개이고, `category='고래 탐사 시즌'`인 퍼즐이 10개다.
