# PRD: 현재 이벤트 도감 필터

## 1. Summary

### Problem

종료된 이벤트 수집품이 일반 수집품과 함께 항상 노출되어 도감 탐색을 방해한다. 기존 이벤트 필터는 단일 선택 드롭다운과 일부 페이지별 전용 스위치가 섞여 있어, 여러 현재 이벤트와 사용자가 다시 보고 싶은 지난 이벤트를 함께 표시할 수 없다.

### Proposed Solution

관리자가 여러 이벤트를 `현재 이벤트`로 지정하는 전용 설정 화면을 제공한다. 도감에서는 일반 수집품과 현재 이벤트 수집품만 기본 노출하고, 사용자가 체크박스형 이벤트 필터에서 지난 이벤트를 추가로 켜면 함께 표시한다.

### Success Criteria

- 관리자가 실제 도감 데이터에 존재하는 이벤트를 복수 선택해 저장할 수 있다.
- 일반 수집품과 현재 이벤트 수집품은 기본 노출되고, 선택하지 않은 지난 이벤트 수집품은 숨겨진다.
- 사용자가 여러 지난 이벤트를 동시에 선택할 수 있고 선택 상태가 브라우저에 유지된다.
- 기존 검색, 정렬, 시간, 수집 숨김 및 카드/표 보기 필터와 이벤트 필터가 함께 동작한다.

## 2. Users And Use Cases

### Primary Users

- 현재 이용 가능한 콘텐츠를 먼저 보고 싶은 일반 사용자
- 과거 이벤트 도감을 다시 확인하려는 일반 사용자
- 배포 없이 현재 진행 이벤트를 변경하려는 관리자

### User Stories

- As a user, I want past event items hidden initially, so that the catalog focuses on currently obtainable items.
- As a user, I want to enable several past events together, so that I can compare or complete their collections.
- As an admin, I want to mark multiple events as current, so that overlapping events appear by default without a deployment.

## 3. Functional Scope

### In Scope

- 이벤트명이 있는 도감 테이블 전체에서 고유 이벤트명 조회
- 복수 현재 이벤트를 저장하는 DB 테이블과 관리자 전용 설정 화면
- 관리자 화면에서 현재 이벤트 복수 선택, 전체 해제 및 저장
- 이벤트 데이터가 있는 목록형 도감의 체크박스형 이벤트 필터
- 이벤트가 없는 일반 수집품 상시 노출
- 현재 이벤트 기본 활성화, 지난 이벤트 기본 비활성화
- 사용자별 이벤트 체크 상태의 브라우저 저장 및 필터 초기화
- 기존 페이지별 고정 이벤트 전용 스위치 제거
- 관리자 화면 진입 링크와 핵심 동작 회귀 테스트

### Out Of Scope

- 이벤트 시작일·종료일에 따른 자동 전환
- 사용자 계정 간 이벤트 필터 동기화
- 수집 도감(`/wiki/checklist`) 자체의 이벤트 필터
- 이벤트 배너, 공지 또는 상세 페이지 노출 정책 변경
- 관리자 임의 이벤트명 생성: 이벤트명은 도감 데이터에 등록된 값만 선택

## 4. Acceptance Criteria

- `/wiki/admin/event-settings`는 `ROLE_ADMIN`만 접근할 수 있다.
- 관리자는 이벤트를 0개 이상 복수 선택해 한 번에 저장할 수 있다.
- 저장 결과는 새로고침 및 서버 재시작 뒤에도 유지된다.
- 이벤트명이 비어 있는 항목은 이벤트 선택 상태와 관계없이 표시된다.
- 현재 이벤트 항목은 최초 방문과 필터 초기화 시 표시된다.
- 지난 이벤트 항목은 최초 방문 시 숨겨지며, 해당 체크박스를 켜면 즉시 표시된다.
- 여러 이벤트 체크박스를 켜면 선택한 이벤트 항목이 모두 함께 표시된다.
- 사용자가 바꾼 이벤트 선택은 로컬 저장소에 보존된다. 관리자가 현재 이벤트를 변경하면 사용자 재정의가 없는 이벤트는 새 기본값을 따른다.
- 현재 이벤트가 하나도 없어도 일반 수집품은 정상 표시되고 이벤트 필터는 사용할 수 있다.
- DB 설정 테이블이 배포 전에 생성되고 애플리케이션 계정에 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 권한이 부여되어야 하며, 둘 중 하나라도 빠진 상태를 정상 운영 상태로 간주하지 않는다.

## 5. Constraints

- Tech: Java 17, Spring Boot, Thymeleaf, Vanilla JS, MyBatis, MySQL 8.0
- Time: 이번 변경은 날짜 자동화 없이 수동 운영 가능한 MVP로 제한
- Data: 기존 각 도감 테이블의 `event_name` 값을 이벤트 식별자로 사용
- External Dependencies: 없음

## 6. Risks

- 이벤트명 오탈자나 표기 차이로 같은 이벤트가 여러 개로 나타날 수 있음: 관리자 화면은 DB의 실제 고유값을 그대로 보여주고 데이터 정리는 기존 관리자 CRUD로 수행한다.
- 새 DB 테이블 또는 애플리케이션 계정의 DML 권한을 적용하지 않고 코드를 먼저 배포하면 조회·저장이 실패할 수 있음: 테이블 생성 및 환경별 권한 SQL 선적용 절차와 검증 쿼리를 배포 안내에 명시한다.
- 기존 페이지별 이벤트 스위치와 새 필터가 충돌할 수 있음: 고정 스위치를 제거하고 공통 이벤트 필터 하나로 통합한다.
- 로컬 저장 선택이 관리자 기본값 변경을 가릴 수 있음: 기본값과 사용자 재정의를 분리해 저장한다.

## 7. Open Questions

- 없음. 현재 이벤트는 관리자 화면에서 반드시 복수 선택 가능하도록 확정했다.
