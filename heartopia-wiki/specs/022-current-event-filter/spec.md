# Feature Spec: 현재 이벤트 도감 필터

## Source

- PRD: `specs/022-current-event-filter/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 0: 일반 항목과 이벤트 조합 선택

- Given 일반 항목과 여러 이벤트 항목이 함께 있다.
- When 사용자가 상세 이벤트 필터에서 `일반`과 원하는 이벤트를 복수 선택한다.
- Then 선택한 종류만 카드와 표에 동일하게 표시된다.

### Scenario 0-1: 상단 빠른 이벤트 전용 보기

- Given 관리자가 빠른 선택 이벤트를 등록했다.
- When 사용자가 빠른 드롭다운에서 이벤트를 복수 선택하고 `해당 이벤트만 보기`를 켠다.
- Then `일반`과 다른 이벤트는 제외되고 선택한 빠른 이벤트만 표시된다.
- When 사용자가 체크를 끈다.
- Then 선택한 이벤트는 유지되고 `일반`이 다시 포함된다.
- And ON/OFF와 이벤트 선택은 한 개의 연결된 분할형 컨트롤 안에서 각각 독립적으로 조작된다.

### Scenario 1: 현재 획득 가능한 도감 탐색

- Given 일반 수집품, 현재 이벤트 수집품, 지난 이벤트 수집품이 함께 등록되어 있고 관리자가 현재 이벤트를 지정했다.
- When 사용자가 이벤트 필터 저장값 없이 도감 목록에 처음 들어온다.
- Then 일반 수집품과 모든 현재 이벤트 수집품은 보이고 지난 이벤트 수집품은 보이지 않는다.

### Scenario 2: 지난 이벤트 여러 개 추가

- Given 이벤트 필터에 현재 이벤트와 지난 이벤트가 구분되어 있다.
- When 사용자가 지난 이벤트 체크박스를 둘 이상 선택한다.
- Then 일반 수집품, 현재 선택된 이벤트, 추가로 선택한 지난 이벤트 수집품이 다른 필터 조건과 교집합으로 표시된다.

### Scenario 3: 사용자 선택 유지

- Given 사용자가 이벤트 체크 상태를 변경했다.
- When 같은 브라우저에서 다른 도감으로 이동하거나 페이지를 다시 연다.
- Then 해당 페이지에도 존재하는 이벤트의 사용자 재정의가 유지된다.

### Scenario 4: 현재 이벤트 변경 반영

- Given 관리자가 이벤트 A를 현재에서 해제하고 이벤트 B를 새 현재 이벤트로 지정했다.
- When 사용자 재정의가 없는 브라우저가 도감을 다시 연다.
- Then A는 기본적으로 숨겨지고 B는 기본적으로 표시된다.
- And 사용자가 명시적으로 켜거나 끈 이벤트는 사용자 선택을 우선한다.

### Scenario 5: 관리자의 복수 설정

- Given 관리자가 이벤트 설정 화면에 접근했다.
- When 실제 도감 데이터에서 가져온 이벤트 여러 개를 체크하고 저장한다.
- Then 선택한 이벤트만 현재 이벤트로 저장되고 모든 도감의 기본 필터에 반영된다.

### Scenario 6: 현재 이벤트 전체 해제

- Given 현재 이벤트가 하나 이상 설정되어 있다.
- When 관리자가 모든 체크를 해제하고 저장한다.
- Then 현재 이벤트 목록이 비워지고 일반 수집품만 기본 표시된다.

## Functional Requirements

- FR-001: 시스템은 물고기, 곤충, 새, 동물, 요리, 꽃, 작물, 채집물, 모래 조각, 바다 청소 도감 테이블의 비어 있지 않은 `event_name` 고유값을 이벤트 목록으로 제공해야 한다.
- FR-002: 관리자 설정 화면은 이벤트별 체크박스와 현재 선택 상태를 표시해야 한다.
- FR-003: 관리자는 이벤트 0개 이상을 한 번에 저장할 수 있어야 한다.
- FR-004: 서버는 제출된 값 중 현재 존재하는 이벤트명만 저장해야 한다.
- FR-005: 현재 이벤트 설정 조회와 변경 엔드포인트는 `/wiki/admin/**` 보안 규칙의 보호를 받아야 한다.
- FR-006: 이벤트 데이터가 있는 모든 목록형 도감은 같은 체크박스형 이벤트 필터 UI와 동작을 사용해야 한다.
- FR-007: 이벤트 필터는 현재 이벤트와 지난 이벤트를 시각적으로 구분해야 한다.
- FR-008: 이벤트명이 없는 항목은 `일반` 선택값으로 표시하고 사용자가 포함 여부를 바꿀 수 있어야 한다.
- FR-009: 이벤트명이 있는 항목은 해당 이벤트 체크박스가 선택된 경우에만 보여야 한다.
- FR-010: 최초 기본 선택은 관리자가 저장한 현재 이벤트 목록이어야 한다.
- FR-011: 이벤트 체크 변경은 로컬 저장소에 이벤트별 사용자 재정의로 저장해야 한다.
- FR-012: 관리자 기본값과 같은 선택으로 돌아온 이벤트의 사용자 재정의는 제거해야 한다.
- FR-013: 초기화 버튼은 검색과 다른 필터와 함께 이벤트 사용자 재정의를 지우고 현재 이벤트 기본값으로 복원해야 한다.
- FR-014: 이벤트 선택은 검색, 정렬, 시간대, 장소, 레벨, 날씨, 수집 숨김 및 보기 방식과 함께 동작해야 한다.
- FR-015: 기존의 `고래 탐사 시즌만 표시`, `데더다만 표시` 같은 페이지별 고정 이벤트 스위치는 공통 이벤트 필터로 대체해야 한다.
- FR-016: 현재 페이지에 관리자 현재 이벤트 항목이 없어도 이벤트명과 `이 도감에 항목 없음` 상태를 현재 이벤트 영역에 표시해야 한다.
- FR-017: 페이지에 이벤트 항목과 관리자 현재 이벤트가 모두 없을 때 이벤트 필터는 비활성 상태를 명확히 표시해야 한다.
- FR-018: 이벤트 지원 도감은 375px 모바일 화면에서 페이지 전체 가로 스크롤 없이 한 열로 읽을 수 있어야 한다.
- FR-019: 다크모드의 검색·선택 입력은 배경과 구분 가능한 글자색을 사용해야 한다.
- FR-016: 관리자에게 헤더에서 이벤트 설정 화면으로 이동할 수 있는 링크를 제공해야 한다.
- FR-017: 필터 트리거는 선택된 이벤트가 없거나 하나 또는 여러 개인 상태를 짧은 문구로 알려야 한다.
- FR-020: 관리자 화면은 현재 이벤트와 빠른 선택 이벤트를 별도 복수 선택으로 저장해야 한다.
- FR-021: 상단 빠른 필터는 관리자가 허용한 이벤트만 후보로 제공해야 한다.
- FR-022: 상단 빠른 필터와 상세 이벤트 필터는 같은 체크 상태를 양방향으로 반영해야 한다.
- FR-023: 빠른 필터를 켜면 선택한 빠른 이벤트만 표시하고, 끄면 해당 이벤트 선택을 유지한 채 `일반`을 포함해야 한다.
- FR-024: 빠른 이벤트의 최초 선택은 현재 이벤트와 빠른 선택 이벤트의 교집합이어야 한다.
- FR-025: 빠른 이벤트가 선택되지 않은 상태에서 전용 보기를 켜면 빈 결과로 전환하지 말고 드롭다운을 열어야 한다.
- FR-026: 빠른 필터는 별도 토글과 선택 상자가 아니라 왼쪽 ON/OFF와 오른쪽 드롭다운이 연결된 단일 분할형 컨트롤로 표시해야 한다.
- FR-027: 왼쪽 영역은 활성 상태와 `ON`/`OFF`를 시각적으로 표시하고 오른쪽 영역은 선택 이벤트명 또는 선택 개수를 표시해야 한다.

## Non-Functional Requirements

- NFR-001: 이벤트 설정 저장은 하나의 트랜잭션으로 전체 교체되어 중간 상태를 노출하지 않아야 한다.
- NFR-002: 서버는 클라이언트가 제출한 임의 이벤트명을 신뢰하지 않고 DB의 실제 이벤트명 목록으로 검증해야 한다.
- NFR-003: 체크박스, 트리거와 드롭다운은 키보드 포커스와 `aria-expanded` 상태를 제공해야 한다.
- NFR-004: 필터 로직은 기존 카드/표 DOM 필터링 구조 안에서 동작하고 별도 네트워크 요청을 발생시키지 않아야 한다.
- NFR-005: 페이지별 이벤트 UI를 중복 구현하지 않고 공통 Thymeleaf fragment와 공통 `WikiFilter` 동작을 재사용해야 한다.
- NFR-006: 375px 화면에서도 분할형 컨트롤이 두 줄로 갈라지거나 페이지 가로 스크롤을 만들지 않아야 한다.

## Edge Cases

- 현재 이벤트가 없음: 이벤트가 없는 일반 항목만 기본 표시하고 모든 이벤트 체크박스는 지난 이벤트 섹션에서 꺼진 상태로 제공한다.
- 이벤트 데이터가 하나도 없는 페이지: 이벤트 필터를 렌더링하지 않거나 빈 상태로 안전하게 표시하며 일반 항목은 모두 보인다.
- 현재 설정에 남아 있지만 도감에서 삭제된 이벤트명: 관리자 화면에서 더 이상 선택할 수 없고 다음 저장 시 제거된다.
- 이벤트명이 앞뒤 공백만 다름: SQL 조회에서 `TRIM`한 값을 기준으로 목록을 만들고 빈 문자열은 제외한다.
- 알 수 없는 로컬 저장값: 현재 이벤트 목록에 존재하지 않는 키는 필터 동작에 영향을 주지 않는다.
- 로컬 저장소 접근 실패 또는 잘못된 JSON: 현재 이벤트 기본값으로 동작하고 페이지 렌더링을 막지 않는다.
- 여러 필터로 결과가 없음: 기존 `검색 결과가 없습니다` 상태를 그대로 표시한다.
- 관리자 폼 중복 제출: 저장 결과는 선택 집합과 동일해 멱등적으로 동작한다.

## Data Requirements

- `wiki_current_events`
  - `event_name VARCHAR(100)` 기본 키
  - `created_at`, `updated_at` 타임스탬프
- 이벤트 선택 후보는 기존 10개 도감 테이블의 `event_name`을 `UNION`하여 조회한다.
- 현재 이벤트 저장은 기존 행을 삭제하고 검증된 선택 집합을 일괄 삽입한다.
- `wiki_quick_events`는 빠른 선택 후보를 같은 구조로 저장하고 현재 이벤트와 한 트랜잭션에서 교체한다.
- 브라우저에는 `이벤트명 -> true/false` 사용자 재정의만 저장하며 계정·개인정보는 저장하지 않는다.
- 브라우저에는 빠른 이벤트 전용 보기 활성 상태도 저장하며 알 수 없는 이벤트 키는 무시한다.

## Clarifications

- Q: 현재 이벤트는 하나만 선택하는가?
  A: 아니오. 운영 중 이벤트 중첩을 지원하기 위해 복수 선택은 필수다.
- Q: 현재 이벤트 설정은 배포 설정인가?
  A: 아니오. 관리자 전용 화면과 DB 저장으로 배포 없이 변경한다.
- Q: `disabled`는 사용자가 선택할 수 없는 상태인가?
  A: 아니오. 지난 이벤트는 기본 체크 해제 상태이며 사용자가 언제든 켤 수 있다.
- Q: 수집 숨김과 이벤트 숨김을 합치는가?
  A: 아니오. 서로 다른 필터로 유지하고 동시에 적용할 수 있게 한다.
- Q: 현재 이벤트와 빠른 선택 이벤트는 같은 목록인가?
  A: 아니오. 관리자가 각각 복수 선택하며 빠른 선택은 종료된 이벤트도 유지할 수 있다.
- Q: 빠른 선택에 아무 이벤트도 선택되지 않았는데 전용 보기를 켜면 어떻게 하는가?
  A: 결과를 모두 숨기지 않고 드롭다운을 열어 이벤트 선택을 요구한다.
