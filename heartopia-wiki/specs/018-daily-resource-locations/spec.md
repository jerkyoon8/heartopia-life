# Feature Spec: 일일 자원 위치

## Source

- PRD: `specs/018-daily-resource-locations/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 현재 위치 확인

- Given 관리자가 현재 게임 날짜의 두 자원 위치를 등록했다.
- When 이용자가 공통 헤더가 있는 페이지를 연다.
- Then 시계 왼쪽에 날짜 없이 `형광석 N번 집 앞`과 `그자리 참나무 유적` 같은 현재 위치가 표시된다.

### Scenario 2: 오전 6시 자동 전환

- Given 오늘과 다음 게임 날짜의 위치가 미리 등록되어 있다.
- When Asia/Seoul 시각이 오전 6시를 지난다.
- Then 새로고침한 페이지와 계속 열려 있던 페이지 모두 다음 게임 날짜의 위치를 표시한다.

### Scenario 3: 미래 위치 예약

- Given 관리자가 관리자 권한으로 로그인했다.
- When 관리자 페이지에서 미래 날짜와 두 위치를 입력한다.
- Then 해당 날짜 예약이 저장되고 예약 목록에서 확인·수정·삭제할 수 있다.

### Scenario 4: 예약 누락

- Given 현재 게임 날짜에 등록된 위치가 없다.
- When 이용자가 헤더를 본다.
- Then 이전 날짜 위치 대신 `위치 정보 없음`이 표시된다.

## Functional Requirements

- FR-001: 시스템은 Asia/Seoul 현재 시각에서 6시간을 뺀 날짜를 현재 게임 날짜로 계산해야 한다.
- FR-002: 시스템은 게임 날짜별로 형광석 위치와 그자리 참나무 위치를 한 행에 저장해야 한다.
- FR-003: 각 위치는 `HOUSE_FRONT` 또는 `RUINS` 유형이어야 한다.
- FR-004: `HOUSE_FRONT` 유형은 1 이상의 집 번호가 필요하고, `RUINS` 유형은 집 번호를 저장하지 않아야 한다.
- FR-005: 공개 헤더는 날짜를 표시하지 않고 두 자원명과 현재 위치만 표시해야 한다.
- FR-006: 시스템은 현재 게임 날짜의 위치를 반환하는 공개 읽기 API를 제공해야 한다.
- FR-007: 클라이언트는 API의 서버 시각을 기준으로 다음 오전 6시 전환 시점에 현재 위치를 다시 조회해야 한다.
- FR-008: 관리자 페이지는 날짜별 위치의 등록·수정·비활성 삭제와 활성 예약 목록을 제공해야 한다.
- FR-009: 같은 게임 날짜를 다시 저장하면 중복 행을 만들지 않고 기존 행을 갱신해야 한다.
- FR-010: 관리자에게만 헤더 위치 영역에서 관리 페이지로 이동하는 편집 링크를 제공해야 한다.

## Non-Functional Requirements

- NFR-001: 관리자 URL과 모든 변경 요청은 Spring Security의 `ROLE_ADMIN` 보호를 받아야 한다.
- NFR-002: 서버의 날짜 계산은 테스트 가능한 `Clock`을 사용해야 한다.
- NFR-003: 헤더 위치 영역은 기존 라이트·다크 테마와 모바일 헤더를 깨뜨리지 않아야 한다.
- NFR-004: 공개 조회는 한 번의 인덱스 조회로 완료되어야 한다.
- NFR-005: 화면에 출력하는 값은 서버에서 생성된 제한된 위치 라벨만 사용해야 한다.
- NFR-006: 열린 탭이 절전 후 복귀해도 다시 보일 때 현재 위치를 재조회해야 한다.

## Edge Cases

- 오전 5시 59분에는 전날 게임 날짜, 오전 6시 정각부터 당일 게임 날짜를 사용한다.
- 두 위치 중 하나라도 유효하지 않으면 전체 저장을 거부하고 관리자에게 오류를 표시한다.
- 같은 날짜를 두 번 등록하면 마지막 저장 값으로 수정된다.
- 현재 예약이 없으면 두 자원 값을 각각 `위치 정보 없음`으로 표시한다.
- 브라우저 시계가 틀려도 최초 API 응답의 서버 시각을 기준으로 전환 타이머를 계산한다.
- 삭제 직후 현재 게임 날짜 데이터가 없어지면 공개 헤더는 다음 조회부터 빈 상태를 표시한다.

## Data Requirements

- 테이블: `daily_resource_locations`
- 고유 키: `game_date`
- 위치 필드: 자원별 `location_type`, `house_number`
- 감사 필드: `created_at`, `updated_at`
- 조회: 현재 게임 날짜 단건, 관리자 전체 목록
- 저장: 날짜 기준 upsert
- 삭제: 관리자만 ID 기준 비활성화하며, 같은 날짜 재저장 시 다시 활성화
- 미래 날짜 상한: 없음

## Clarifications

- Q: 공개 헤더에 예약 날짜를 표시하는가?
  A: 표시하지 않는다. 날짜는 내부 예약과 오전 6시 전환에만 사용한다.
- Q: 위치는 자유문구인가?
  A: 아니다. `N번 집 앞` 또는 `유적`만 가능하다.
- Q: 관리자는 어디서 입력하는가?
  A: 별도 관리자 페이지에서 날짜별 예약을 관리한다.
- Q: 현재 날짜 데이터가 없을 때 이전 값을 유지하는가?
  A: 유지하지 않고 `위치 정보 없음`을 표시한다.
