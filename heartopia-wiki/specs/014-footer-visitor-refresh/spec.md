# Feature Spec: 공통 푸터 및 접속자 통계 재배치

## Source

- PRD: `specs/014-footer-visitor-refresh/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 서비스 안내 탐색

- Given 방문자가 공통 푸터가 있는 페이지의 하단에 도달했을 때
- When 푸터를 살펴보면
- Then 사이트 소개, 이용 안내, 문의 경로, 법적 고지를 구분해서 확인할 수 있다.

### Scenario 2: 접속자 통계 확인

- Given 서버가 주간 및 오늘 접속자 통계를 제공할 때
- When 방문자가 푸터 하단을 확인하면
- Then 주간과 오늘 수치가 각 라벨 및 아이콘과 함께 쉼표 형식으로 표시된다.

### Scenario 3: 모바일 이용

- Given 화면 너비가 768px 이하일 때
- When 푸터가 렌더링되면
- Then 주요 섹션과 하단 상태 영역이 세로로 재배치되고 콘텐츠가 잘리거나 가로로 넘치지 않는다.

### Scenario 4: 향후 헤더 정보 확장

- Given 운영자가 추후 시간·날씨 정보를 상단 내비게이션에 추가하려 할 때
- When 현재 헤더 구조를 확인하면
- Then 기존 접속자 통계가 차지하던 오른쪽 영역이 비워져 있다.

## Functional Requirements

- FR-001: 시스템은 모든 기존 공통 푸터 사용 페이지에 새 푸터 구조를 제공해야 한다.
- FR-002: 푸터는 사이트 이름과 비공식 가이드 성격을 소개해야 한다.
- FR-003: 푸터는 문의 게시판, 이메일 문의, 개인정보 처리방침 링크를 제공해야 한다.
- FR-004: 푸터는 기존 게임 콘텐츠 저작권 및 비공식 팬사이트 고지의 의미를 유지해야 한다.
- FR-005: 푸터는 `weeklyVisitors`와 `todayVisitors`가 존재할 때 두 통계를 표시해야 한다.
- FR-006: 통계 숫자는 Thymeleaf 숫자 포맷을 이용해 천 단위 구분 기호를 표시해야 한다.
- FR-007: 헤더는 접속자 통계 마크업을 더 이상 렌더링하지 않아야 한다.
- FR-008: 현재 작업은 시간·날씨 UI나 데이터 조회를 추가하지 않아야 한다.

## Non-Functional Requirements

- NFR-001: 푸터 스타일은 `.site-footer` 범위로 제한해 기존 페이지 컴포넌트와 충돌하지 않아야 한다.
- NFR-002: 밝은 테마와 어두운 테마에서 본문, 보조문, 링크, 테두리를 읽을 수 있어야 한다.
- NFR-003: 링크와 통계 항목은 키보드 탐색과 스크린 리더가 이해할 수 있는 텍스트를 제공해야 한다.
- NFR-004: 새 외부 라이브러리, 이미지 요청, API 호출을 추가하지 않아야 한다.
- NFR-005: 768px 이하 및 480px 이하 화면에서 반응형으로 배치되어야 한다.

## Edge Cases

- `weeklyVisitors`가 `null`이면 접속자 통계 묶음 전체를 숨기고 나머지 하단 고지는 정렬을 유지한다.
- 통계 값이 0이면 `0`으로 표시한다.
- 이메일 주소가 길어도 모바일 너비 안에서 줄바꿈되어야 한다.
- 어두운 테마에서는 푸터 배경 효과가 과도하게 밝아지거나 텍스트 대비를 해치지 않아야 한다.
- 본문 길이가 짧은 페이지에서도 기존 상단 여백과 푸터 간격이 유지되어야 한다.

## Data Requirements

- 기존 `GlobalControllerAdvice`의 `weeklyVisitors`, `todayVisitors` 모델 속성만 사용한다.
- 접속자 집계, 저장, 조회 SQL 및 서비스 로직은 변경하지 않는다.

## Clarifications

- Q: 참고 이미지의 개발자 프로필·후원 링크도 추가하는가?
  A: 실제 대상 URL이 없고 이번 요청은 분위기와 하단 배치가 핵심이므로 추가하지 않는다.
- Q: 비워진 헤더 영역에 시간·날씨 자리표시자를 넣는가?
  A: 넣지 않는다. 후속 기능을 위해 접속자 카운터만 제거한다.
- Q: 참고 이미지의 그라데이션을 그대로 복제하는가?
  A: 복제하지 않는다. 현재 사이트의 분홍·크림 계열과 다크 테마 변수를 활용해 별도 디자인으로 만든다.
