# Feature Spec: 업적 수집 항목 숨김 우선순위 수정

## Source

- PRD: `specs/023-achievement-hide-collected-threshold/prd.md`
- Principles: `specs/principles.md`

## User Scenarios

### Scenario 1: 별점 기준치가 설정된 업적 카드 숨김

- Given 사용자가 업적을 달성했고 전역 숨김 기준치를 1~5로 설정했다.
- When 사용자가 업적 페이지에서 `수집된 항목 숨기기`를 켠다.
- Then 달성한 업적 카드는 별점 기준치와 무관하게 숨겨진다.

### Scenario 2: 테이블 보기에서도 동일하게 숨김

- Given 달성한 업적이 있고 수집된 항목 숨기기가 켜져 있다.
- When 사용자가 테이블 보기로 전환한다.
- Then 해당 업적 행도 카드와 동일하게 숨겨진다.

### Scenario 3: 별점 도감 기준치 유지

- Given 별점 기능이 있는 도감 항목과 `3성 이상 숨김` 설정이 있다.
- When 0성 수집 항목과 3성 수집 항목을 필터링한다.
- Then 0성 항목은 보이고 3성 항목은 숨겨진다.

## Functional Requirements

- FR-001: 시스템은 수집 여부 판정 전에 해당 항목의 별점 지원 여부를 파악해야 한다.
- FR-002: 별점 미지원 항목은 수집된 경우 설정된 별점 기준치를 적용하지 않고 숨겨야 한다.
- FR-003: 별점 지원 항목은 기존 `N성 이상 숨김` 기준을 유지해야 한다.
- FR-004: 업적 카드와 테이블 행은 동일한 업적 체크리스트 키로 상태를 조회해야 한다.
- FR-005: 명인 달성 필수 설정은 기존 지원 항목에 대해 현재 동작을 유지해야 한다.

## Non-Functional Requirements

- NFR-001: 숨김 판정은 DOM 및 저장소를 추가 순회하지 않는 상수 시간 연산이어야 한다.
- NFR-002: 판정 핵심은 브라우저 없이 실행 가능한 회귀 테스트로 검증해야 한다.

## Edge Cases

- 미수집 업적: 기준치와 무관하게 노출한다.
- 업적 체크 값 `0`: 유효한 수집 상태로 처리해 숨긴다.
- 별점 도감 체크 값 `0`: 기준치가 1 이상이면 기존처럼 노출한다.
- 별점 도감 값이 기준치 이상: 숨긴다.
- 기준치가 없거나 `0`: 모든 수집 항목을 기존처럼 숨긴다.

## Data Requirements

- 기존 `heartopia_checklist`의 `{key: 0..5}` 저장 형식을 유지한다.
- 업적의 키 형식 `achievement_{name}`을 카드와 테이블에서 공유한다.
- 별점 미지원 여부는 렌더링된 요소의 데이터 속성으로 제공한다.

## Clarifications

- Q: 업적의 체크 값 `0`을 별점 0으로 취급해야 하는가?
  A: 아니다. 업적은 별점을 지원하지 않으므로 `0`은 단순 달성 상태다.
- Q: 기준치 설정을 업적 페이지에서 무시해야 하는가?
  A: 그렇다. 기준치는 별점 지원 수집도감에만 적용한다.
